# 节点故障接管与实时窗口容量

## 本轮需求与实现边界

节点异常时，只将仍期望运行的任务在其他符合准入条件的节点重新建立连接，不搬迁旧日志。旧日志继续以原节点目录登记，原节点不可访问时历史读取应明确报告不可用，不伪造迁移完成或文件完整性。

自动接管必须先有精确旧运行的连接关闭证明，或可信的基础设施隔离证明。心跳超时不能区分机器停机和网络分区，不能直接释放旧归属。对仍可访问的Worker尝试受鉴权的精确运行关闭请求；数据库失联时已主动关闭的Worker保留关闭证明用于恢复后处理。完全失联且无法确认连接关闭仍保持等待隔离。

新运行使用新的运行和会话标识，初始化命令重新执行，定时预算按新运行重新开始。暂停、停止、资源删除及认证失败不得被自动恢复覆盖。迁移候选仍遵循节点容量、专用资源路由、写入压力和NFS能力，排除本次故障原节点；没有可用候选时等待，不隐式回到异常节点。

## 实时窗口

删除前端每秒200行和固定5000行的主动省略规则，正常收到的数据按原序全部进入有界展示缓冲。默认每窗口10MiB，管理员可在后台设置`liveLogBufferMiB`（整数1至100）；容量收紧时立即丢弃最旧部分，保留最新内容。该预算针对日志内容及索引估算，不承诺浏览器总RSS等于配置值。

正文保存仍走独立采集写入链，不受浏览器容量限制影响。网络断线、慢连接或服务端游标过期造成的缺口继续显式提示并提供补读，不把这些缺口隐藏成正常全量显示。渲染采用虚拟窗口和批量更新，禁止每行复制或移动整个大缓冲。

`GET /api/v1/display-settings`仅向已登录用户公开实时容量配置，不放开管理员设置读取权限。实时页面打开时读取并每30秒更新，切换任务和卸载取消旧结果，管理员保存后已有页面在下一轮更新生效。

## 后台配置导航

沿用现有表单和保存确认规则，改为横向模块导航：平台与容量、节点准入、资源监控、记录保留。每次只显示选中模块；切换时保留未保存草稿，窄屏导航可横向滚动，组件和弹窗保留各自滚动边界。平台与容量中保存实时日志内存上限；下调后即使窗口暂停或正在查找，也裁剪旧显示快照，暂停标志保持不变。

## 验证计划

- 两节点旧连接确认关闭后新节点新运行；无证明、关闭失败、旧代次、暂停停止和并发控制不误接管。
- 原节点文件保持原路径，新节点日志单独登记，不复制旧正文。
- 高频1200行每秒输入连续性与保留后缀、长行、多字节、动态缩容、旧会话和传输重叠。
- 普通用户只能读取展示配置，管理员版本化保存，非法容量拒绝。
- 桌面及移动端模块切换、容量保存、实时列表滚动与查找；前后端回归及隔离真实协议冒烟。
