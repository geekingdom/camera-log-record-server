# 开发产物清理

真实设备日志遵循平台保留策略；资源软删除继续保留已有日志。开发合成数据清理与产品行为独立，禁止为清理压测数据缩短全局保留期。

## 已自动处理

- 小时归档经摘要、大小校验、原子发布与目录同步后删除原始子日志；压缩失败保留原文件。
- `benchmark_service.py` 写出完整性及收尾报告后删除本轮下载副本。性能不达标仍保留失败报告。
- 执行 `python scripts/cleanup_dev_artifacts.py` 预览已有候选；加 `--apply` 执行。
- 脚本只扫描实验根目录下一层，有认可的压测 scope、逐路摘要一致、完整性通过且 `cleanup.json` 无错误时，删除对应路由的 `route-NNNN-hour-NNN.archive`。忽略符号链接及不完整报告，保留报告、指标和诊断证据。

## 服务端合成归档

下载副本脚本不清理服务端目录。使用独立入口，只传入有完整来源证据的实验目录：

```sh
.venv/bin/python scripts/cleanup_dev_server_logs.py --report .local/已完成实验目录
.venv/bin/python scripts/cleanup_dev_server_logs.py --report .local/已完成实验目录 --apply
```

可重复传入 `--report`，不会扫描或猜测其他任务。脚本读取当前节点的 MongoDB、`LOG_ROOT` 和节点 ID 配置；不修改全局保留期，也不创建采集连接。

执行条件：报告、收尾、资源 ID 与任务索引一致；资源软删除已完成；所有任务永久停用、停止且无节点归属；整个归档组属于报告内任务；路径位于本节点日志根且不含符号链接；旁路成员清单与目录身份一致；实际解压正文的源摘要、行数和逐路序号再次验证通过。

默认返回预览。`--apply` 仍会重新核验所有条件；未来下载保护期或活动作业返回 `PROTECTED`，不清除保护。领取使用 `READY + retainUntil` 条件更新为 `DELETING`，并复用维护流程删除完整小时归档、旁路清单、索引及目录记录。空 ID 集不扩大扫描；共享归档含未批准成员时整组保留；自然保留天数可跳过，但未来小时不清理。

执行请求和完成记录写业务审计，标准输出返回 `removed/skipped/failures`。完成记录代表本次处理结束，实际删除数量以返回值为准。文件删除中断后已领取的 `DELETING` 由正常维护流程重试；预检缺失完整目录记录会拒绝再次推断来源，不能以重新构造报告或递归删除绕过。
