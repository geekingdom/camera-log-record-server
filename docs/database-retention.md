# MongoDB 增长型记录保留策略

设备日志正文、小时归档和 NFS coredump 源文件保存在 Worker 文件系统，不进入 MongoDB；MongoDB 保存任务配置、文件目录、认证历史和排障元数据。认证历史、审计事件、运行事件、命令执行记录和操作记录会随运行时间增长，因此按集合分别治理，避免一个全局 TTL 误删仍用于恢复的记录。

## 默认行为

认证历史默认按90天（约三个月，不是日历月减法）保存，新记录写入绝对过期时间；Mongo TTL 异步删除，接口会先隐藏已过期记录。`AUTHENTICATION_RECORD_RETENTION_DAYS=0` 时新记录不写过期时间。配置变更不修改旧记录已经保存的过期时间；升级前没有 `expiresAt` 的历史记录需执行下文回填，查询会先按当前90天策略限制可见范围。

审计、运行事件及已结束运行的默认保留期由后台 `platform_settings.recordRetention` 管理：`auditDays`、`eventDays`、`runDays` 默认均为90天，取值`0`表示关闭该类自动维护。维护循环每5秒读取最新配置，每轮最多处理100个运行候选以及每个普通集合100个候选；这是为了限制单轮数据库负载，不等于保证数据在到期瞬间删除。请求排障事件仍使用固定30天 TTL。

请求对象展示补充 `targetKind`、`targetLabel`、`targetScope` 及路由声明的 `targetId`，任务/资源/节点同时保留对应关联ID；每次HTTP请求仍仅一条记录，不增加写入频率。对象ID最多128字符，不读取查询或正文，沿用30天TTL。页面先按既有时间/请求条件分页，再批量读取当前页对象名称；没有新增对象筛选或排序，因此不额外建立未被查询使用的索引。历史集合类型在读取时由路由推导，缺失的实体ID不猜测、不批量回填。

## 长期增长分层

批量添加海康设备复用既有集合，不增加逐次认证预览历史。一次成功批次至多256台，按每个设备写入资源、地址占用、认证头及初始认证历史、创建审计；这些记录与一条成功幂等映射在同一事务提交。映射仅保存最多256个资源ID，不保存请求密码，沿用7天`expiresAt`和`actor,key`唯一索引；认证历史与审计分别沿用各自保留策略。失败批次不创建资源，仅按失败IP记录安全审计。重放沿用资源`id`查询，没有新增集合或查询索引；规模随创建资源数和失败操作数增长，不按设备日志行数增长。

每个会持续产生记录的集合必须先归入下列一层，再允许写入正式库。不能把设备日志正文、协议收发字节、实时展示行或 coredump 内容放入 MongoDB；它们由 Worker 文件系统的小时归档、文件目录和下载任务管理。MongoDB 只保存足以定位、查询、审计和恢复的元数据。

| 层级 | 集合或记录 | 当前治理 | 查询与容量边界 |
| --- | --- | --- | --- |
| 配置与当前状态 | `resources`、`tasks`、`nodes`、`node_configs`、模板和用户 | 永久保存；软删除记录保留删除时间与创建人 | 以稳定 `id`、资源关联和状态索引读取；不保存每次状态轮询的副本 |
| 可压缩历史 | `authentication_records`、未来的周期性健康汇总 | 全部周期认证结果按资源、UTC 日和身份连续区间聚合，90 天 TTL | API与认证页面使用 `createdAt,id` 游标；一次认证区间存首末时间与次数，不逐次展开 |
| 有恢复依赖的事件 | `commands`、`operations`、`budgets`、`runs`、任务运行事件 | 已结束运行按配置分段归档；运行、未知命令、有效幂等映射和活动引用受保护 | `UNKNOWN` 命令、隔离、预算和接管判断完成前不得按终态 TTL；归档摘要与本批明细删除必须同一事务提交 |
| 审计与排障事件 | `audit`、`events`、`request_events` | `audit`、`events`按后台策略限量维护；请求事件固定30天 TTL | 审计删除前写入固定字段 gzip 摘要；管理页必须限定时间范围、稳定排序和最大返回量；事件正文不得保存密码、令牌、命令密文或日志正文 |
| 短租约及临时产物 | 登录会话、幂等键、下载会话、导出/快照 claim 与产物 | 以 `expiresAt` TTL 或既有租约收尾 | TTL 只负责无业务依赖的临时数据；物理文件删除须由拥有者确认，不能仅依赖 TTL 回调 |

认证记录只是这一策略的第一类落地对象。新增类似“每分钟探测”或“周期性巡检”功能时，默认采用固定时间桶、连续状态边界和计数汇总，保留状态变更、失败、人工操作及设备身份变化的单独事件。每个桶必须保存首见、末见、次数、版本和不可变过期时间；不能通过更新 TTL 让长期连续成功的单条记录永久存在。

调试模式与NFS例行检查在同一采集会话中只记录首次正常确认，连续相同的`ALREADY_ASH`和`MOUNTED`不再生成分钟事件；任务健康字段和NFS检查时间继续更新。去重缓存仅在事件成功写入后推进，新会话、失败、恢复和实际重挂开启新的状态边界，失败重试仍逐次保留。不清理历史重复记录，不改变命令执行审计，也不增加集合或TTL。

Coredump 每个已登记文件版本只生成一次 `COREDUMP_DISCOVERED`，记录资源、文件ID、相对文件名、节点、首次发现时刻及当时大小，不记录文件正文或主机绝对路径。增长上界为目录中新增文件版本数，不按5秒扫描频率增长；沿用`events`默认90天维护。事件以确定性主键重试，目录记录保存成功标记，避免事件到期清理后每轮复活。旧目录在再次观察时可补记，时间沿用原`receivedAt`。事件写失败不会阻断其他文件扫描。

资源看板复用既有`resources`、`tasks`、`files`、`coredump_files`和`nodes`，不新增集合、TTL或持续写入流程。看板的上海日原始日志查询以既有`files(taskId,hour)`索引先按可读任务ID和小时范围缩小候选，`archiveBytes`不参与统计；高频多用户刷新在进程内短暂合并相同权限和窗口的只读快照。每日 Core 统计使用新增`coredump_files(receivedAt,resourceId)`索引，以`receivedAt`范围先筛选后按资源分组，仍在应用层执行与列表一致的可见性条件。该索引增加每次 Coredump 目录写入和状态更新的维护成本；上线前必须在真实 Mongo 对 30 天窗口运行`explain("executionStats")`，确认时间范围为`IXSCAN`候选、无阻塞排序，并记录扫描键/文档数和索引大小。看板不把短时本机 Explain 当作长期容量验收。

资源存在性筛选在分页前用资源ID关联目录，关联子管道至多返回一个主键；不把全部文件列表带入资源文档。周期源文件复核使用`coredump_files(nodeId,id)`游标索引，每轮有界探测，只有确定的文件缺失才撤销存在状态；Worker失联或目录不可访问时保留最后已知状态。`verify_coredump_discovery.py`在随机真实Mongo库验证筛选分页、重复发现和Explain后清理实验数据。摘要/对象模糊查询不盲增B-tree索引；事件对象关联候选每类最多1000，超过返回422要求细化条件，不静默截断或枚举整个文件历史。

## 集合级生命周期与容量预算

不能仅因为记录带有时间字段就设置 TTL。每个增长集合先明确“是否仍被恢复流程、下载会话或物理文件引用”，再选择分桶、摘要归档或删除策略。下表是当前实现和后续演进的唯一约束；其中“规划”表示**尚未启用自动删除**，不得据此清理线上数据。

| 集合 | 增长来源与写入上界 | 当前查询与索引 | 生命周期决策 | 后续归档或清理前置条件 |
| --- | --- | --- | --- | --- |
| `authentication_records` | 周期认证、人工认证、凭据失败和身份变化；连续相同周期结果按资源、UTC 日和身份压缩 | 按资源、结果、身份变化、`createdAt,id` 游标；`expiresAt` TTL | 已启用固定90天 TTL；聚合区间不会续期 | 旧数据先低峰回填绝对过期时间；TTL 延迟删除期间接口按截止时间隐藏 |
| `resource_metric_hours` | 启用资源监控的资源每分钟最多一项样本；每资源每 UTC 小时最多60样本、一个文档 | `resourceId,bucketStart` 倒序读取；`expiresAt` TTL | 已启用固定保留期，默认90天；同一分钟重试覆盖，不新增样本 | 采样身份变化直接丢弃；仅在真实集群测得 BSON 和索引大小后调整保留期，不能把原始命令响应写入桶 |
| `events` | 状态转换、连接异常、隔离、挂载、磁盘压力及`SLAVE_SSH_BOOTSTRAP`引导终态；必须按状态变化写入，禁止按日志行写入 | 默认及 task/node/type/requestId 的 `createdAt,_id` 稳定排序索引 | 按`recordRetention.eventDays`限量维护，默认90天；`0`关闭维护 | 活动任务、未结束运行、非终态命令及端点锁引用时保持；候选扫描和删除均按`createdAt,_id`书签推进 |
| `audit` | 用户、服务账号和管理员的变更、控制、下载审计 | action/actor/target/requestId 加 `createdAt,_id` 索引 | 按`recordRetention.auditDays`限量维护，默认90天；`0`关闭维护 | 删除与`audit_archive_chunks`摘要、日删除计数同事务提交；不得用 TTL 绕过归档与引用保护 |
| `commands`、`operations`、`budgets`、`runs` | 初始化、定时和手动命令；任务控制、预算预留与运行实例；每次受控 Worker 部署每个精确旧 owner 最多一个关闭证明 | 任务、命令配置、类型、状态、运行/会话和时间索引；部署阶段按部分索引`deploymentRecovery.token,nodeId`查询，原始日志恢复按`deploymentClosedProof.nodeId`查询 | 已结束运行按`recordRetention.runDays`分段归档，默认90天；`0`关闭维护 | 未持久化原始日志恢复 spool 的关闭证明通过`archiveRecoveredAt`保护 run；spool 已落盘后恢复可幂等重试，run 按既有分段归档，不永久积累。`UNKNOWN`、未结算预算、非终态操作、未结束运行、有效幂等映射和端点锁继续受保护 |
| `run_archives`、`record_purge_days`、`record_archive_maintenance` | 结束运行归档摘要、按日删除计数、维护租约和书签 | `runId`唯一、任务/结束时间及维护文档精确键读取 | 摘要随业务保留；计数和书签由维护作业持续覆盖，不累积明细正文 | 摘要只累计数量、状态与时间等有限字段；游标、租约和revision用于恢复与并发互斥 |

| `log_gap_snapshots` | 实时日志缺口目录的短游标快照 | `taskId`和随机快照ID精确读取，`expiresAt` TTL | 1小时 TTL；不保存日志正文 | 仅保存已授权任务、两端锚点、文件范围和续页位置；超时要求重新定位 |
| `jobs`、下载/快照 reservation 与 claim | 搜索、日志下载和 coredump 导出；租约续期与物理临时文件协作 | node/status/lease、创建时间及 token 精确索引 | 临时会话和部分导出记录已有 TTL；`jobs` 本体保留 | 必须先确认执行租约关闭、产物已删除或已发布、取消/失败原因已落审计；TTL 只能清理无业务依赖的临时令牌，不能替代物理文件回收 |
| `coredump_files` | NFS 扫描发现、稳定性状态转换、快照读者与导出状态 | 资源接收时间、节点状态、来源版本和快照 token 索引 | 目录元数据跟随 coredump 文件保留，当前不设 TTL | 先完成源文件、冻结副本、活动下载和导出引用的原子核验；物理文件成功删除后才可删除目录元数据，失败时保留可排障状态 |
| `request_events` | 每个 HTTP 请求的脱敏观测记录 | route/status/task/clientIp/requestId 与时间索引 | 已启用固定30天 TTL | 不保存请求正文、密码、令牌或设备输出；TTL 有延迟，查询仍按时间范围限制 |

### 高频分桶规则

对“每 N 秒一次”的新记录，默认按资源（或任务）和 UTC 自然小时/日分桶，桶内使用稳定子键覆盖同一采样窗口的重试结果。桶需要同时满足以下限制：

- 固定最大项数和固定最长时间范围，单文档始终远低于 MongoDB 16 MiB 上限；超出时创建顺序分片，而不是无界追加数组。
- `expiresAt` 只由桶起点和配置的保留期计算一次；后续更新不得续期。
- 一次采样只保存可查询的结构化指标、状态码和脱敏错误分类。原始设备输出、完整命令响应和日志正文留在文件系统或短期受控调试通道。
- 查询只按桶范围读取，再在应用层展开有限样本；API 必须限制最大时间范围、页大小和导出量，并使用时间游标而不是深层 `skip`。

资源监控是该规则的基线：假设500个资源均启用，每资源每天固定产生24个小时桶，90天上限约为1,080,000个桶、64,800,000个分钟样本。实际容量应按“每桶 BSON 字节数 + 每个索引字节数”测量，不能只按样本数量推断。默认指标项或进程数增加前，必须用目标规则下的满60样本桶测量文档大小并审查 `resourceId,bucketStart` 索引占用、写入 P99 和副本集复制延迟。

### 清理作业的统一协议

除 MongoDB TTL 外，所有终态历史清理均采用同一维护作业协议。增长记录维护使用`record_archive_maintenance`中的 owner、expiresAt、revision 与持久 keyset 书签取得租约；每一条候选在事务内再次读取、写入租约栅栏并检查最新状态。运行明细以每批100条命令或预算分段归档；审计、事件和操作每类每轮最多处理100个候选。审计删除与 gzip 摘要及`record_purge_days`日计数同事务提交。维护循环运行失败、取消或失去租约时，下轮从持久状态重新检查，不能在用户请求中执行无筛选的`delete_many`。

恢复引用检查至少包含：活动运行、任务锁、未决命令、预算、操作、下载/导出作业、冻结快照、文件目录和审计关联。任一检查不能确定时，候选项保持不删除并记录原因；这比为节省空间删除可能仍影响恢复或下载的元数据更重要。

## 写入、查询与归档门槛

高频记录的设计先以记录数、平均 BSON 大小、索引数和保留天数估算容量，而不是仅以业务功能判断是否入库。设计评审至少记录以下预算：

- 峰值写入速率与正常写入速率，包括 API 重试和 Worker 并发写入；认证成功聚合后应按“资源数/日”而非“探测次数/分钟”估算。
- 单条文档与每条索引的实际大小。索引不是免费副本，新增一个复合索引会同时增加每次插入、更新和 TTL 删除的写入成本。
- 默认列表、筛选和导出的最大时间范围、最大页大小和是否需要精确总数。深分页不得用不断增大的 `skip`；优先游标、按需总数或异步统计。
- 线上样本的 `explain("executionStats")`、慢查询、索引大小和副本集复制延迟。临时库 `IXSCAN` 仅是候选索引信号，不是长期容量验收。

当某类有恢复依赖的记录达到业务确认的保留窗口后，采用“先摘要、后分批删除”的两阶段方案：先把可长期查询的聚合摘要或导出清单写入独立集合/对象存储，完成恢复引用检查和抽样还原验证，再按稳定时间键、限量批次删除原始终态记录。删除作业要记录开始/结束时间、查询条件、删除数量、错误和恢复依据，并提供预览模式；不得在 API 请求内执行大范围 `delete_many`，也不得把 TTL 当成归档成功确认。

运行事件新写入统一使用 `createdAt`。旧 `detectedAt` 可通过下文工具补齐到缺失/null的 `createdAt`；存在未迁移记录时仍采用兼容派生排序，迁移完成后自动使用持久时间索引。三类管理事件已支持显式游标，默认不count或skip；旧页码API兼容且仍有精确总数和深分页成本。游标以实际时间及原始BSON主键续页，混合字符串/ObjectId按类型组处理，筛选先于limit；低选择性派生查询及旧时间兼容路径仍可能扫描大量候选。`scripts/verify_event_cursor.py`真实Mongo同时间245条跨10页完整，第5页一次查询26键/26文档，无blocking SORT；此为小样本证据而非容量证明。审计与运行事件的自动维护统一以后台`recordRetention`生效配置为准，而非旧环境变量的候选计划。

## 连接原因事件的增长预算

`IDLE_TIMEOUT`、`READ_ERROR`与`CONNECTION_GAP`复用`events`，仅在状态变化时写入，不按设备日志行数写入；使用已有taskId/nodeId/type与createdAt索引，不新建同类索引。原因事件仅保存任务/运行/会话/节点、固定说明和结果等级，不保存设备正文或原始错误文本。正常稳定连接没有这类周期写入。

`TASK_AUTO_MIGRATED`同样复用`events`，只在领取新节点的事务中每次实际迁移写入一条，记录旧/新节点及任务、运行，不在围栏重试时追加事件。500路同时迁移产生500条，稳定运行期间无该类增长；沿用现有任务/事件类型与时间索引及默认90天事件维护和恢复引用保护，不新增TTL。任务上的关闭证明、故障原节点和重试时间为覆盖更新的固定大小字段，成功领取后清除迁移标记，不建立逐次重试历史集合。

持续异常仍有增长成本：以500路均每10秒触发一次空闲阈值粗略估算，不计登录/退避时间时，每类每天约432万条；原因加通用缺口两条记录约864万条。实际速率受连接、初始化和重试时间影响。该估算不是容量验证；部署须结合真实BSON、索引和复制成本监测。运行事件现由增长记录维护器按配置期限、稳定书签和恢复引用保护限量清理，不能给整个`events`集合直接统一TTL。

`SLAVE_SSH_BOOTSTRAP`同样复用`events`，每次从机引导尝试最多写入一次命令提交、一次服务结果和一次从机连接完成，不按命令队列等待、SSH握手字节或日志行写入。字段仅限任务/运行/资源/节点/端口关联和固定阶段结果，不保存密码、引导token、设备输出或异常正文；按现有`taskId`、`nodeId`、`type`与时间索引查询，不新增索引。500路在每路每分钟一次完整重连的保守上界为每天216万条，实际应以目标环境重连频率、BSON、索引占用和复制延迟验收；当前不设TTL，后续清理前仍须确认未知引导、隔离和恢复引用已不再依赖事件。

## 连续相同结果聚合

合并同一资源、同一UTC自然日内连续且结果相同的周期认证，包含SUCCESS、AUTH_FAILED、OFFLINE和ERROR，要求型号和序列号一致且没有身份变化。结果发生变化、首次认证、手动认证、编辑认证和身份变更均开启独立段，不跨过这些边界继续累加。例如离线、离线、成功、离线形成三段，次数为2、1、1。按日分段固定到期时间，避免无限延长历史寿命；持续相同结果每天通常只保留一条周期记录，实际数量受状态变化、迟到观测及人工操作影响。

错误说明不同但结果相同仍合并，`message`更新为最近一次说明，次数覆盖整段而非每一种具体异常。已有历史记录不批量重写或删除；新观测可在满足条件时继续累计现有末段。没有新增集合或索引，沿用每资源head串行事务和既有时间/结果/身份索引。固定TTL不因失败次数增长而续期。

聚合条目的 `createdAt` 是该段首次认证时间，`latestAt` 是最近一次时间，`occurrenceCount` 是整段累计次数；`id`、首次时间和 `expiresAt` 不随累加改变。连续边界以同一资源认证结果的数据库提交顺序定义；完成时间早于当前段最近观测的迟到结果另起一段，避免时间检索漏掉该观测。`latestAt` 始终取该段最大的观测时间。筛选时间区间时，返回与该区间相交的整段记录，次数不是所选子区间内的精确次数。旧记录没有聚合字段时按一次认证展示，不从旧数据推测补造次数。身份字段允许为空，按空字符串统一比较。

`authentication_record_heads` 每资源固定一条，以资源ID作为Mongo主键，保存最新事件指针和递增代次。每次认证在同一事务内先写该头记录，再插入或累加历史；并发写冲突会重试，避免失败插入与成功累加写入不同文档而跨过状态边界。迟到的完成时间不会回写到已有成功区间。该头集合随资源数量增长，不随认证次数增长，不能对其设置与历史相同的TTL。

## 已落实索引

认证页面首屏显式发送 `cursor=`，后续用 `nextCursor` 前后翻页，接口返回 `total=null`，不执行总数统计和深层 `skip`。页面只保存当前页正文及已访问页的起始游标，上一页重新请求；不提供精确总数和任意跳页。旧页码API保留兼容，其count/skip成本仍存在。游标不是数据库快照，认证累加、新增或TTL到期可能改变前后页内容；刷新会重新读取首屏。

| 集合 | 主要查询路径 |
| --- | --- |
| `authentication_records` | 资源ID，结果/身份变更的可选组合，`createdAt,id`稳定倒序；`expiresAt` TTL |
| `audit` | 默认`createdAt,_id`倒序，action/actor/targetId/requestId筛选与同样排序 |
| `request_events` | 默认时间倒序，taskId/httpStatus/route/clientIp/requestId筛选与稳定排序；保留30天TTL |
| `events` | 默认`createdAt,_id`倒序，以及taskId/nodeId/type/requestId筛选及相同排序；未迁移时间兼容限制见下文 |
| 任务、文件、作业、命令 | 保留既有调度/领取、任务小时、作业租约、命令预算及历史查询索引，没有盲目新增重复索引 |

事件索引集中在 `common/event_indexes.py`，认证与既有索引在 `common/database.py`。2026-09-11本机数据库已实际安装新增索引，15条无过期时间的旧认证记录完成回填，复跑待处理数为0。旧前缀索引保留，不能只因新复合索引有相同前缀就无依据删除。

## 升级已有数据

索引由 API/Worker 的 `Repository.initialize()` 幂等安装。旧认证记录缺少过期时间或值为 `null` 时，部署后在工程环境执行：

```sh
python scripts/backfill_authentication_expiry.py
python scripts/backfill_authentication_expiry.py --apply
```

第一条仅预览；第二条每批最多500条读取并逐条补齐 `createdAt + AUTHENTICATION_RECORD_RETENTION_DAYS`。单次默认最多5000条，可用 `--max-records` 调整（最高100000）；结果 `limitReached=true` 时继续运行直至没有待处理记录。使用工程 `.env` 中的数据库配置；不打印凭据，不覆盖已有过期时间，不修改日志、core或其它集合。过期记录随后由Mongo TTL删除，因此该迁移是应用90天保留策略的操作。中断后可以重跑，已处理记录不会再次改写；保留配置为0时工具拒绝执行，避免意外给永久记录设置到期时间。大库迁移由单个维护进程在低峰分批执行，当前没有全局迁移租约。

## 查询和清理原则

认证新记录会写入固定 `expiresAt` 并由 MongoDB TTL 自动过期；连续成功聚合不会更新该字段。`common/record_maintenance.py`已启动独立维护循环：每5秒读取平台配置，单轮限制30秒，并通过租约和事务调用`record_archive.py`、`record_purge.py`。单轮上限为每类100个候选，运行归档另以100条子记录分段推进；这避免长时间扫描阻塞节点心跳、设备认证和采集调度。命令、操作、预算、幂等映射和运行记录只会在明确终态、归档摘要可用且无恢复引用时进入处理。

清理应与恢复流程协调：命令的 `UNKNOWN` 结果、操作的失败/取消终态和认证变更历史是排障证据，默认保留；如果业务需要缩短期限，应先导出审计摘要并在低峰分批执行。MongoDB TTL 适合无业务依赖的请求排障事件，不适合活动状态或需要事务判断的集合。

## 增长集合 Explain 验证

## 新集合与流程约定

2026-09-20节点性能策略：复用节点配置与`nodes`心跳记录，覆盖写入固定大小的`performance`和`performanceStatus`，不新增历史集合或逐次指标文档。写入阶段每项最近1024个样本只留在Worker内存，心跳保存摘要；归档排队仅内存持有活动作业计时，完成即移除。节点ID的既有唯一查询索引满足热配置读取，不新增无查询依据的索引。管理员变更沿用已有设置审计和保留策略，不对运行节点或任务恢复引用增加TTL。

2026-09-18归档全文候选索引：不新增Mongo正文集合，每个小时包旁保存一个SQLite FTS5 contentless索引及成员最多首尾各16字节的边界证据，每包上限256MiB，随归档保留清理删除。构建前最低384MiB空闲，构建中保留128MiB；失败回退原文查询。索引无任务恢复或幂等依赖，可由不可变归档重建，不进入下载附件。增长为每个小时包最多一个索引，真实比例应实测，不能将单样本推广为容量承诺。

旧包补建在nodes保存固定大小的searchIndexCursor，每轮最多读取64条目录、构建一个小时包，不随运行时间追加历史。files新增(nodeId,status,id)索引覆盖READY目录游标查询；真实Mongo1000条测试返回64、keysExamined=64、docsExamined=64，无阻塞排序，见`scripts/verify_search_index_catalog.py`。没有对仍被查询/归档/恢复引用的files增加终态TTL。

- 建集合时同时记录增长速率、记录大小、保留期、是否被任务恢复或幂等映射引用，避免先无限写入再补清理策略。
- 根据实际查询的等值字段、范围字段、排序和稳定次排序键建立复合索引；必须覆盖默认列表，不能只优化带筛选的页面。
- 针对每个可选字段组合建索引会放大写入与磁盘成本。优先常用路径，使用真实Mongo `explain`核对扫描量和阻塞排序，再决定新增索引。
- 同规格索引升级保留旧名字，检查TTL和partial/sparse等选项；多进程重复初始化必须可复用，不能无条件删除旧索引。
- 事件或计数压缩必须有明确的连续状态边界及并发串行点；失败、身份变更和用户操作不能被成功聚合覆盖。
- TTL不提供准点删除保证，查询需考虑可见性；有预算、租约、幂等和恢复引用的记录不得仅按终态直接TTL删除。
- 普通子串或忽略大小写的正则搜索无法指望普通B-tree索引消除全扫描；规模增长后应单独评估搜索索引和查询限制。

## 运行事件时间回填

部署升级全部API/Worker后，在低峰使用工程环境执行：

```sh
python scripts/backfill_runtime_event_time.py
python scripts/backfill_runtime_event_time.py --apply
```

默认预览，写入每批最多500条，单次默认最多5000条，`--max-records`最高100000。仅将标量BSON日期`detectedAt`复制到缺失或null的`createdAt`，保留原检测时间，已有创建时间始终优先。没有可靠时间或日期为数组的旧记录不造时间，报告`unmigratable`供人工检查。CAS同时核对读取时的原值，避免覆盖并发变化。`remaining`是仍可迁移数量；重复执行直至为0，不在API启动时进行无界回填。

查询每次通过默认时间索引检查旧格式记录，没有旧格式时直接按`createdAt,_id`排序；旧记录仍在则保留`$ifNull`派生排序。不缓存迁移标记。没有创建时间但存在非空无效检测时间的记录仍会触发兼容路径，需要单独核查；两种时间都缺失的记录不推断时间。分页与探测不是同一个数据库快照，因此升级期间应先更新全部写入端，不能保证旧版本在探测后并发插入旧格式记录时的单次查询一致性。

派生结果/级别筛选的持久时间排序前置到表达式计算之前，筛选之后才执行skip/limit，以允许索引有序读取；该路径仍需计算结果、扫描候选并统计总数，不能宣称其成本只等于返回条数。`scripts/verify_runtime_event_time.py`使用真实Mongo随机库验证回填前后列表/时间筛选等价及Explain，结束删除临时库；生产索引大小、写入成本、深分页及低选择性筛选仍须另行验收。
