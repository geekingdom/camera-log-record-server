# 主从设备SSH日志采集

任务字段`sshTarget`取`HOST`（默认）、`SLAVE_1`、`SLAVE_2`或`SLAVE_3`。主机任务始终直连配置的IP和端口，不创建额外服务。从机1/2/3分别通过主机上的dbclient连接192.168.253.164/166/167，内部用户名固定admin，密码采用该任务提供的设备密码。

## 连接与恢复

资源文档以CAS保存`slaveSshPort`，当前默认18080，允许范围18080至18084。已有从机任务复用同一端口。该字段每资源一个，不随采样或重连新增数据库记录，无需新集合或TTL。任务保存`effectiveSshPort`和最近从机登录时间供诊断，用户配置的主机入口端口保持原值。

每次从机连接先探测共享端口；失效时资源文档CAS选出一个引导者，120秒租约配合90秒本地操作上限及发送前token核验，其他从机等待共享端口就绪。主机任务正在恢复时先等待其初始化（最长20秒），然后优先借用主机SSH命令队列执行固定dropbear命令。跨Worker通过带内部令牌、请求任务run/generation、引导token及主机归属检查的专用接口借用，接口不接受任意命令或口令。

远端借用的整体执行上限为45秒，覆盖主机命令队列的排队和命令响应；调用端HTTP等待为55秒。远端明确返回主机或运行资格失效时才允许调用端退回临时原端口引导。网络断开、响应超时、响应损坏、远端超时或5xx均属于**结果未知**：调用端不再发送临时dropbear，并保留当前资源的引导token直至120秒租约到期。远端整体上限短于该租约，因此同一任务重连或新代次不能在可能仍有远端动作时重叠引导；到期后由新的CAS引导者重新探测和恢复。所有真实SSH连接均受实际IP/端口的五名额限制。租约状态每资源至多一条嵌入对象，不产生历史增长，旧引导者只能清理自己的token。

扩展服务始终绑定同一个端口，重复启动的bind失败不会产生另一个端口服务；启动后仍探测SSH监听，不以命令返回成功代替服务可用。设备重启或服务失效后按相同流程恢复。从机停止不关闭资源共享dropbear，以免中断同端口其他任务。

外层主机先识别ASH，仅PSH尝试已有debug流程。随后发送`dbclient admin@内网IP -y; exit`，严格等待目标地址的密码提示并只发送一次密码，确认新的ASH或PSH横幅后才交给日志采集器执行初始化。初始化及定时配置中的debug复用已有流程，处理从机自身的挑战数据。`exit`保证内层SSH退出后外层shell随之退出，不会把主机打印当作从机日志。

引导阶段只有一个底层接收协程，确认前的数据只存在有界握手窗口；确认后的从机数据通过有界队列交给原日志链路。取消、密码失败、超时均关闭底层连接，关闭不确定仍走现有隔离流程。从机不执行Coredump或CPU/内存资源监控，主机SSH和既有Telnet设备任务继续承担这些功能。

## 排障事件

从机引导的关键终态写入`events`集合，固定`type=SLAVE_SSH_BOOTSTRAP`。每条事件只含`taskId`、`runId`、`generation`、`resourceId`、请求任务`nodeId`、`sshTarget`、`port`、可选`hostTaskId`和`hostNodeId`，以及固定枚举`phase`、`outcome`、`level`和中文`message`。`HOST_BORROWED`与`TEMPORARY_BOOTSTRAPPED`表示管理命令已提交，结果为`UNKNOWN`；只有`SERVICE_READY`与`SLAVE_CONNECTED`表示成功。租约等待超时、服务未就绪、整体超时和跨节点结果未知/取消分别生成固定失败或未知事件，未知远端请求仍由原有`finally`保留租约。

事件写入最多等待0.2秒，数据库异常只记录不带异常正文的节点日志，不能改变建连、关闭、租约清理或取消语义。事件不保存设备密码、引导token、内部认证头、设备响应正文、SSH输出或任意异常字符串。每次引导尝试最多产生一次命令提交、一次服务结果和一次从机连接完成事件；失败路径只记录已知的单一终态，不按重试循环、握手字节或日志行写入。

## 验收范围

需要验证主机22不变、多个从机共用扩展端口、从机登录前不执行初始化、登录失败不采集主机正文、扩展服务失效后恢复，以及暂停/停止回收连接。35仅有从机1，可用于真实验证；从机2/3不能以35成功代替真实设备验收。
