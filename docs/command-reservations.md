# 定时命令预算事务

定时命令在发送队列轮到自己时，先通过 `commands/reservation.py` 原子预留预算和执行记录，确认提交后才允许设备写入。执行次数是最多进入发送阶段的次数，不代表设备业务成功次数。

## 持久化边界

事务使用 MongoDB 副本集、snapshot 读取和 majority/journal 确认。首先按任务、运行、节点、代次、会话和采集意图条件递增任务的 `commandClaimVersion`，与停止、暂停及归属变更形成写冲突；再递增该运行与命令的预算，并插入 `SCHEDULED/SENDING` 执行记录。预算耗尽或配置移除使事务回滚。执行 ID 在可重试回调外生成，驱动重试不生成额外身份。

原先在预算递增与执行记录插入之间取消，会留下无记录的已消耗次数。现在两者整体提交或回滚。事务返回未知结果时不退回次数、不补建记录、不写设备连接；异常携带原执行 ID，由发送器将实际存在且仍为 SENDING 的记录标为 UNKNOWN。实际未提交时该更新为空操作。原始数据库异常记入服务日志。

该事务只覆盖数据库，不把设备 socket 写入伪装为数据库事务的一部分。确认提交之后仍可能断线或进程崩溃，因此预算不保证设备业务成功；会话收尾和节点隔离继续负责处理无法确认的 SENDING 记录。数据库持续不可用时，结果回写必须等待数据库恢复及收尾处理，不能宣称即时完成。

## 验证

执行 `.venv/bin/python scripts/verify_command_reservation.py`。脚本只创建随机临时库和内存设备替身，结束后删除临时库，不访问真实设备。已接入容器 CI，验证：

- 预算递增后取消及执行记录插入后取消，均不遗留部分提交。
- 重连后预算连续累计、耗尽后拒绝、不同任务预算独立。
- 固定事务快照后提交停止意图，冲突重试不得占用预算。
- 真实提交后模拟应答丢失，通过正式发送器和定时循环确认设备写入为零、唯一执行记录转为 UNKNOWN、预算仍为一次。

部署涉及采集 Worker。更新前对正在运行的 SSH 任务使用暂停，确认连接释放后停止旧 Worker；启动新版后恢复原任务，保持运行 ID 与定时预算。禁止新旧 Worker 同时占有同一设备会话。
