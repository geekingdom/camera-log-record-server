# 调度领取事务与恢复

单个任务的运行锁、任务归属和运行记录在 MongoDB 副本集事务中提交，采用 snapshot 读取及 majority、journal 写入确认。调度器只负责选点和维护本周期容量；领取逻辑集中在 `backend/camera_logs/tasks/claim.py`。不支持事务的数据库应报错，禁止降级为多次独立写入。

## 取消和提交未知

旧实现可能在插入运行锁后取消，留下阻止下次启动的锁；也可能在更新任务归属后取消，使任务已有节点但运行记录缺失。现在事务取消时整体回滚，后续周期可重新领取。提交应答丢失时，数据库中的三项状态要么全部提交，要么全部未提交；调用方结束本周期，并在下一周期重新读取已确认状态，不通过事务外删锁补偿来猜测结果。

新运行 ID 在可重试事务回调外生成，驱动重试不会额外生成运行。SSH 和 Telnet 设备暂停恢复沿用原运行 ID 与命令预算，并在事务中清理旧恢复令牌；事务会重新检查最新任务状态，停止或资源删除先提交时不得继续领取。分配成功后才增加本周期占用计数。

## 调度者隔离

每次取得或续期调度租约都递增 fence。单任务事务首先以 owner、fence 和有效期为条件写入 leader 文档；接管操作与旧领取事务修改同一文档，产生冲突。驱动重试时必须重新检查租约，旧代次失效就结束周期，不能继续使用旧容量快照。只读租约检查无法建立此写冲突约束。

这用于隔离调度者，不替代采集节点的物理隔离，也不授权在设备连接结果未知时迁移任务。部署升级时应先停止旧版 API 调度进程，再启动新版，避免不支持事务 fence 的旧代码与新版同时分配。采集 Worker 可继续运行，已有设备会话不需要为本次 API 升级重连。

## 验证

执行 `.venv/bin/python scripts/verify_scheduler_transaction.py`。脚本只操作随机临时库，结束后删除临时库并关闭连接，已接入容器 CI。它使用真实 MongoDB 验证：

- 锁写入后、任务 CAS 后分别取消，三项记录与 leader 领取版本均回滚，随后可正常领取。
- 普通领取与重复领取的身份一致性；暂停恢复保持运行 ID 和预算，任务与运行代次同步推进。
- 真实提交后模拟应答丢失，下一周期不创建重复运行。
- 过期或被替换的 owner/fence 被拒绝，真实快照写冲突后旧调度者不能提交。
- 领取期间事务外提交停止意图，重试不覆盖停止状态，也不留下孤立运行资源。

MongoMock 的共享事务替身仅用于测试状态分支，不能证明事务原子性。上述真实副本集验证才是取消、冲突和提交一致性的验收依据。
