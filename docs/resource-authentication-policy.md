# 资源认证与周期退避策略

海康网络资源由后台周期认证确认可用性。每次网络请求都在数据库事务外执行，完成后
只有持有当前健康租约令牌的结果才能提交；迟到结果不会覆盖用户继续操作、新租约或
新设备身份。资源文档中的 `healthFailureCount` 和 `nextHealthCheckAt` 是持久状态，API
健康认证调度进程重启后从同一字段继续，不依赖进程内计时器。

## 周期认证间隔

连续的**周期认证**非成功结果，无论归类为 `AUTH_FAILED`、`OFFLINE` 或 `ERROR`，均
递增 `healthFailureCount`。下一次周期认证按累计次数安排：

| 连续失败次数 | 下次认证间隔 |
| --- | ---: |
| 1 至 9 次 | 60 秒 |
| 10 至 21 次 | 300 秒 |
| 22 至 45 次 | 3600 秒 |
| 46 次及以后 | 86400 秒 |

周期认证成功会将 `healthFailureCount` 置为 `0`，并把 `nextHealthCheckAt` 设为成功后
60 秒。状态字段 `healthStatus` 仍照认证结果更新；状态没有变化的连续失败也必须保留
递增计数，不能因避免重复停止任务而意外清零。

恢复任务的即时探测优先于上述退避。继续操作将资源的 `nextHealthCheckAt` 置为到期，
已在执行的旧认证完成时会保留该即时到期请求，不能把它推迟为成功或失败的默认间隔。

## 手动认证

已有资源的正式入口为：

```text
POST /api/v1/resources/{resourceId}/authenticate
```

资源列表可发送空请求体。服务端要求资源写权限、任务控制权限及创建者/管理员授权，
提交事务内拒绝非管理员影响他人创建的关联任务；完整请求体的编辑预览维持原权限。
通过授权后，从资源中读取并
解密已保存的凭据，客户端不读取、缓存或回传密码。此形式成功时在同一事务中更新
健康状态、清零 `healthFailureCount`、设定 60 秒后的周期检查、写入手动认证历史和
成功审计。完整 `ResourceInput` 请求体仍兼容资源编辑流程的认证预览。

空请求体的手动认证失败会更新资源健康状态、写入认证历史和失败审计，并按既有资源
健康规则停止关联的运行任务；它不递增周期失败计数，也不会改变已经安排的周期退避。
完整 `ResourceInput` 预览失败只写入手动认证历史和失败审计，不修改保存资源。这样
重复点击即时认证不会把设备推入更长的自动探测间隔。

## 数据与保留

退避只增加资源文档中的两个标量字段，不新建周期尝试明细集合。认证结果沿用
`authentication_records`：周期成功按资源、UTC 日和连续状态聚合，失败和手动操作
单独保留，并遵守 [数据库保留策略](database-retention.md) 的固定 90 天认证历史 TTL。
认证记录不保存密码、HTTP 请求头、设备响应正文或日志内容。
