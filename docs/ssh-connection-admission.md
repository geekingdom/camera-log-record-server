# SSH 设备连接名额与生命周期

## 适用范围

平台所有已更新 Worker 共用 MongoDB 中的设备级五连接上限。同一 IP 使用不同端口、不同资源或不同任务，也只共享五个名额；IPv4/IPv6地址先规范化。其它程序建立的连接不受平台控制，因此五名额不是对设备外部终端连接数量的探测。

`collection/ssh_admission.py` 在 `ssh_connection_slots` 中以设备IP作主键，单文档条件更新保证最多五个占位。每个占位保存任务、运行、代次、节点及唯一token。该集合每IP一条文档、每条最多五个占位，只需默认主键索引，不随日志行数增长；不设置TTL，不按心跳或占位年龄回收。

## 建连与收尾

Worker在真正调用AsyncSSH前占位。满额时不建立socket，任务保留等待重试，错误信息指出设备名额已满；成功采集后清除等待错误。数据库占位结果未知时禁止新建socket，并进入BLOCKED，不能使用新的token重复尝试。

AsyncSSH的 `client_factory.connection_made` 在连接阶段捕获句柄，认证未完成时取消也能主动关闭。只有 `wait_closed()` 成功后才归还名额。shell创建失败、初始化失败、暂停、停止和正常重连共用关闭链路；关闭超时或异常会主动abort，但abort不是关闭确认，不提前归还名额。关闭后的数据库释放失败可以通过同一连接对象继续重试。

平台使用Mongo名额作为跨节点准入，不叠加独立工具的本地池。直接调用连接适配器而没有仓储时仍保留当前事件循环内按地址的五连接保护；该独立模式不证明跨Worker上限。

## 故障恢复

失联并不等于旧设备socket已经断开。数据库或关闭结果未知时保留占位，运行的停止流程不能因为工厂没有返回连接对象就写入关闭收据。已有BLOCKED恢复路径只有在精确关闭收据或管理员确认实际隔离后，才按任务ID、runId及generation释放该旧运行的残留占位。不会删除后继运行的占位。

平台不能代替基础设施证明断电、网络隔离或进程终止。管理员必须先完成实际隔离，再提交隔离确认；不得直接删除数据库占位来绕开这一边界。Telnet不使用SSH名额。

## 升级顺序

1. 在维护窗口暂停或停止旧版本SSH任务，等待连接和日志收尾完成。
2. 更新API与全部Worker；新版本Worker自动使用同一Mongo库的名额集合，无需新增环境变量。
3. 恢复SSH任务，确认同IP第六路等待，停止或暂停一路后名额归还。

旧版本已建立的socket没有登记记录，因此不能一边保留旧版本采集会话、一边声称全平台限制已生效。多个Worker必须连接同一平台数据库。节点使用majority写入，结果未知不能视为占位成功。

## 验证入口

- `tests/test_ssh_admission.py`：五名额、精确释放、未知提交、取消准入。
- `tests/test_ssh_slot_lifecycle.py`：关闭失败不归还、重试确认后释放、握手阶段取消、重复关闭与准入前拒绝第六路。
- `tests/test_ssh_admission_runtime.py`：未知占位不能生成关闭收据，Worker进入BLOCKED。
- `scripts/verify_ssh_admission.py`：真实Mongo、两个独立进程竞争，跨端口同IP上限和旧运行清理隔离。
- `scripts/verify_ssh_socket_admission.py`：真实回环SSH服务器与Mongo，五路实际shell、第六路拒绝、归还后重新接入、最终socket与占位归零。

两个脚本均只使用随机临时库，结束后清理，不访问实体设备或产生采集日志。此证据不等同于真实Linux多机故障隔离验收。
