# 审计页会话修复与业务审计事务

本轮代码基线 `345aa8e`。最新用户问题为审计与事件页面提示“登录会话已失效，请重新登录”。本记录区分用户问题与同期 R26 工作，不能把后者的部分完成当成全平台审计一致性已交付。

## 审计页面

`frontend/src/features/audit/api.ts` 原先自行执行 fetch，无论是否存在服务 Token 都发送 `Authorization: Bearer ...`。Cookie 登录会清除旧 Token，空 Bearer 因后端认证优先级覆盖正常 Cookie，引发 401。现复用 `shared/api.ts`，仅非空 Token 才发送 Bearer，Cookie 使用同源凭据。真正的带 `X-Auth-Required` 的 401 走统一登录失效流程；403 不触发退出。

新增 5 项单元测试，覆盖两个端点、非空 Token、真实失效及权限不足。修复前 3 项失败，修复后 5 项通过；前端全量 47 项和生产构建通过。

`scripts/browser_audit_session.mjs` 在随机独立数据库、临时 API/Vite 和临时日志目录上运行，显式要求隔离标志、URL 和临时管理员凭据。真实 Chrome 完成首次登录、改密确认、Cookie 身份检查、审计筛选/详情与运行事件切换；两个接口均为 200，请求无 Authorization，未出现页面异常。已检查 1440×1000 和 390×844 截图。临时进程、数据库和目录均已回收，没有连接设备或生成设备日志。

本机现有浏览器页面在刷新前仍显示旧的失败行为；刷新后进入登录界面，因此没有把隔离成功冒充为现有用户会话成功。未修改真实管理员密码，用户重新登录后使用新请求代码。

## 事务边界

- `audited_mutation` 将资源编辑/软删除意图、模板编辑/删除、账户创建/编辑/重置/删除/自行改密与审计放入同一个快照读取、majority+journal 提交的 Mongo 事务。
- `audited_create` 将资源/模板对象、幂等 SUCCEEDED 映射和审计原子提交。prepare 在事务外只运行一次，回调重试复用固定对象 ID。快速重放与结果未知恢复都使用主库 majority 读取。
- 资源停止扫尾在删除意图和审计提交后执行，失败留下可重试 PENDING；再次删除不重复创建审计。设备认证、加密和密码哈希在事务外；Cookie 签发在已确认密码变更后执行。
- 同键异体、未确认映射返回 409；成功映射对象已删除返回 410；无法确认提交返回 503。一般编辑接口提示先查询最新状态，不能错误承诺支持同键重试。
- 既有 `Repository.idem`、定时预算与手动命令事务未整体替换。登录/退出、任务控制、配置、IP 规则等仍待审查，设备 socket 执行结果仍可能未知。

`scripts/verify_audited_mutations.py` 在真实 Mongo 副本集的随机临时数据库通过：审计失败回滚资源插入/模板编辑/账户删除、取消回滚、12 并发同键只产生一个对象和审计、异体冲突、失败同键重试、真实事务重入但 prepare 单次执行、已删除对象 410、丢失提交确认后的同键恢复、不同键同名模板 409 且无残留映射/额外审计。finally 删除数据库后才输出成功；已加入 Linux container-smoke。

MongoMock 不支持事务，共享夹具仅适配异步数据库和执行回调，不模拟回滚。全量测试曾发现局部 with_options 适配遗漏，已统一到共享夹具。另一个同名冲突测试依赖回滚，已转入真实副本集验证，避免用假回滚当原子性证据。
