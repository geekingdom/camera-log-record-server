# 资源列表浏览器验收同步修复

## 失败与复现

提交2921616的CI35502758638仅frontend失败，断言为“第二页应保留多选状态”，实际1条、期望2条，其余七个作业成功。

原脚本固定等待100ms后仅检查请求已发出，没有等待响应和表格刷新，并按整个表格复选框序号点击。本机原速度通过；给模拟列表响应增加600ms延迟后，先在“不存在筛选结果不得显示coredump红点”断言复现旧表格读取，证明请求已发出不能作为页面就绪证据。独立审查未发现当前业务分页后的同页多选需要修改。

## 修改

- 明确等待预期请求参数、加载遮罩结束和目标页IP列表完全一致。
- 按资源名称定位行，点击可见复选框并等待选中，保留最终两条选中和批量删除按钮可用断言。
- 默认模拟响应延迟600ms，使CI持续覆盖慢响应场景，可通过RESOURCE_RESPONSE_DELAY_MS覆盖。

## 验证与边界

600ms延迟专项通过，覆盖筛选、清空、分页、多选、排序以及1920/1440/1024/390/320宽度截图；node语法检查和git差异检查通过。生产构建22项全页面回归通过，桌面和移动端截图已检查，独立审查无阻断项。修复提交CI待核验。浏览器API全部模拟，无真实设备操作或采集日志产物。
