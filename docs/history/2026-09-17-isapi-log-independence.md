# ISAPI 与采集连接独立判定

## 最终行为

资源的 `healthStatus` 继续如实表示 ISAPI 认证结果。应用崩溃导致 HTTP 无响应、401或异常响应，不再直接停止已经领取的 SSH/TELNET_DEVICE 运行。Worker 使用原有唯一接收器的真实字节与连接状态判断，正常输出时持续采集，不额外 ping 或建立探测 SSH 连接。

当 ISAPI 为 AUTH_FAILED、OFFLINE 或 ERROR，且 Worker 已确认日志连接断开或持续无输出时，才通过事务提交系统停止。默认观察窗口为10秒；断连有收尾与重连宽限，不承诺严格第10秒完成停止。新运行提供观察期，同一运行持续静默不会被无输出的重复重连无限重置。每次原始接收在写盘前登记；存储背压不算设备静默，真实写入/同步结束后重新观察。接收、观察与 Worker 全部使用同一 `time.monotonic()`，不能混用事件循环时间或节点墙钟。

停止事务重新核对资源当前结果、运行/节点/代次、控制版本、RUNNING意图和最新本地接收证据。认证已恢复、日志已恢复、任务已换代或用户已暂停/停止时，过期请求不覆盖当前状态。检查由 Worker 持续执行，不等待已退避为小时或天的下一轮HTTP认证。数据库/节点失联仍沿用现有围栏与恢复机制，不以缓存的COLLECTING状态证明设备在线。

未领取或新启动的SSH/Telnet设备任务仍受资源认证准入限制。用户暂停/停止语义不变；系统因OFFLINE停止后的恢复继续沿用已确认身份与关闭证明，AUTH_FAILED/ERROR停止仍需要用户成功认证授权。TELNET_SERIAL不受HTTP认证结果、认证恢复或身份变化控制，创建、启动和领取也不因此被拦截；资源主动删除仍属于独立管理操作。

正在采集的SSH主机/Telnet设备连接继续承担已开启的Coredump与CPU/内存监控，HTTP错误本身不触发NFS卸载。原有资源删除/监控开关、租约、会话、任务状态和主机限制保留。周期HTTP状态变化使用`resource_health_changed:*`审计，只有真正提交任务停止时才写`resource_health_stop:*`。

## 验证与边界

`verify_isapi_log_independence.py` 使用随机Mongo库、真实回环HTTP/SSH源和正式API/Worker。分别注入401、503、HTTP服务停止，核对仍在同一采集会话；随后停止日志源并把下次认证延迟到次日，验证Worker自动收尾并逐行比对归档。最终运行通过，单个归档内54行与源端完全一致；临时Mongo库和日志根均已回收。正式CI接入该脚本。

最终后端全量1556项、Ruff、差异检查通过。真实Mongo资源停止/恢复事务脚本覆盖用户stop竞争、未收尾锁保护、退避边界、人工认证及事务回滚。32路×1200行/秒×3秒合成校验通过，115200行、29491200字节原文，采集实际3.001秒、含归档3.159秒，逐路摘要与时间前缀正确；TemporaryDirectory退出已清理所有合成文件。独立审查未发现阻断问题。本机无活动任务/归属/作业后受控重载，API/Worker健康200，local-dev新心跳有效。

实现期间真实验证发现本机uvloop事件循环时钟与Python单调时钟起点不同，混用会使接收年龄失真；统一时钟后重新验证。对慢写盘的检查还发现空闲重复fsync会不断重置观察期，已改为仅存在未持久化字节时同步。早期失败实验均通过finally回收隔离进程、随机库和临时采集文件，没有操作实体设备或保留模拟日志堆积。

本轮不将本机模拟源验证等同公司设备应用崩溃、真实NFS传输或500路全天容量验收。没有批量更改历史任务意图；升级前已被旧策略停止的任务仍按原恢复标记处理。
