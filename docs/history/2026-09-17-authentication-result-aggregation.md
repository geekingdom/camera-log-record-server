# 全部周期认证结果的连续合并

## 需求与实现

此前仅PERIODIC/SUCCESS合并，AUTH_FAILED、OFFLINE、ERROR每次新建。现相同资源、UTC日、身份的连续相同周期结果均累计occurrenceCount；createdAt与expiresAt固定，latestAt和message代表最近观测。结果变化、首次认证、人工/编辑认证、身份变化、跨日或迟到观测仍新段。离线、离线、成功、离线得到三段，次数2、1、1。旧历史不批量删除或改写，新观测允许在符合条件的当前末段续计。

复用authentication_record_heads每资源逻辑串行点和既有事务，不新增集合或索引。失败持续时的写入数量与日内连续状态段数相关，不再与每次探测次数成正比；90天TTL不随累计续期。API返回字段与前端次数显示兼容，仅更新字段说明。

## 验证

三个新失败结果测试先复现逐条插入错误，修复后认证历史、健康状态、手动认证审计和API参考相关66项通过。真实Mongo副本集脚本验证四种结果各16并发，只形成1条16次；不同消息合并保留最近说明；成功/失败交替为3、2、4、3，计数和head边界正确；TTL保持不变。随机实验库在finally删除，无设备操作或采集日志产生。

验证脚本已接入cross-worker-read CI作业。全量回归最终结果以当前状态总表为准，目标部署需更新API服务；Worker不负责资源HTTP周期认证记录的写入。
