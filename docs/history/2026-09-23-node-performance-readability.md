# 节点性能状态可读性优化

## 问题

节点页面把性能控制器的`THROTTLED`统一显示为“限流中”。该状态既可能表示当前仍有CPU、内存或写入压力，也可能表示历史压力已经消失、后台读取预算正在稳定恢复。用户看到“写入延迟低于上限、CPU和内存正常”时，无法判断节点是否仍被保护性降速。

## 实现

性能心跳现在同时上报：

- `pressureActive`：当前采样是否仍满足压力条件；
- `budgetReduced`：有效预算是否低于当前安全基准；
- `baseline`：当前资源和管理员策略共同形成的基准预算；
- `recoveryStableSeconds`：当前无压力后连续稳定的秒数。

节点看板按这些事实显示“当前压力”“等待恢复”“恢复中”“已恢复”和“手动参数”，并显示后台读取有效值与基准值的比例。新字段只改善解释，不改变写入顺序、准入阈值、自动降速和恢复策略。

## 验证

后端性能专项21项通过，前端全量186项通过，生产构建和全仓Ruff通过。覆盖当前压力、历史降级后的稳定窗口、手动参数和基准预算比例展示。
