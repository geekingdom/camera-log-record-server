# 节点管理与小时归档时区

## 需求与原因

用户完整部署出现 `compose-worker-1 / http://worker:8001`，这是 Compose 默认值；`.env.worker` 仅由独立入口加载，网页登记不启动新进程。原登记模型禁止非环回 HTTP，与默认部署矛盾。用户追加要求删除节点，并询问 UTC 18:30 为什么显示次日02点小时档。

## 实现

- HTTP(S) 节点登记支持 Docker 服务名、内网 IPv4/IPv6；仍拒绝凭据、附加路径和通配监听地址。登记响应合并已有真实心跳。
- 首次生成的完整 `.env` 明确列出 COLLECTOR_NODE_ID/URL 及配置文件边界，不改写现有配置。
- 节点软删除与审计、禁用准入共同提交；删除和领取都写同一节点文档，事务冲突后重新检查。保留历史目录和节点地址，后续心跳不自动恢复。未结束运行、任务归属和未释放连接拒绝删除，显式重新登记支持恢复，陈旧删除版本拒绝。
- 前端删除二次确认，取消不写入，正在删除时防重入；动作按钮宽度固定。
- 小时列标注北京时间 UTC+8，归档仍按 Asia/Shanghai；用户样例对应次日02:00–03:00，未修改服务器时钟。
