# 部署整数字符串解析修复

起点：915e60c。检查远端CI发现986af5c的运行34566195593在完整容器、独立组件和原生部署失败；原生日志明确显示node_capacity='100'、cluster_capacity='500'、retention_days='7'被严格整数校验拒绝。915e60c的运行34567697159同样出现三项部署失败，不能沿用更早绿色CI描述当前部署状态。

## 原因和修复

Settings中六个容量/保留字段使用strict=True，而环境变量和dotenv提供字符串。本机既有测试多用Python整数直接构造配置，因此未覆盖真实部署来源。

在Settings新增字段前置校验，仅把ASCII十进制整数字符串解析为int，然后继续执行原有严格类型与上下界校验。支持首尾空白和正负号；负数仍由范围拒绝。布尔值、浮点值、小数和科学计数文本不会被转换。平台JSON配置请求模型保持不变。

## 证据与范围

- CodeGraph sync及Settings影响分析完成；共享配置影响面较大，因此执行后端全量验证。
- 进程环境和dotenv测试在修复前2失败，错误与CI一致；48项非法输入测试原先通过。
- 修复后50项新测试和相关专项共70项通过，后端全量1227项通过（108.66秒），Ruff及diff通过，独立审核无阻塞问题。
- 本机Linux aarch64 Docker容器通过只读挂载当前backend，真实传入六个环境变量，Settings值全部匹配；容器使用--rm且禁用网络，没有生成采集日志或测试卷。
- 本轮没有前端改动，前端107项及构建为915e60c已有证据，不表述为本轮重跑。
