# 登录审计、资源筛选、归档阅读与趋势图片验收

## 需求与实现

1. 登录失败审计保存请求中填写的用户名到 `metadata.username`，失败身份仍为 anonymous。错误密码、无效账号及限流均覆盖；不记录密码和请求正文。审计详情直接显示填写用户名，运行时事件合同包含字段中文释义。
2. 所有用户打开资源页默认“查看全部”；“仅查看自己”与其互斥，按当前认证身份匹配创建者或显式共享用户，“包含已删除资源”独立。API `mine=true` 与其他筛选取交集，分页与统计在服务端执行，不用前端过滤当前页冒充全量结果。
3. 已归档日志交互打开成员时不再先扫描整个gzip包尾。节点保留独占解压流和每流512KiB尾部，兼容查看器128字节重叠及上一段；文件指纹、身份、成员和水位隔离不变。浏览器仅对READY文件缓存最多8段，关闭/切换清空，重新读取绕过缓存。
4. 日志分片默认10MiB不变，10至510按5MiB档位，另接受512MiB端点。后续新分片按既有Worker缓存刷新机制生效，历史归档不改写。
5. 趋势面板CSV右侧新增导出图片，复用当前指标、时间范围、缩放和图例选择，输出独立于屏幕宽度的清晰PNG，包含完整标题、设备、时间范围、坐标及折线。

## 验证进度

后端全量2136项通过，新增冻结水位/EOF尾部回看后归档专项30项通过；前端212项通过。真实隔离Worker、WebSocket和浏览器小时下载通过，随机数据库与临时日志目录已回收。资源筛选四种组合真实Explain通过：全部当前/含删除均20条返回、20键20文档；本人及共享当前/含删除均20条返回、21键20文档，流式SORT_MERGE无阻塞排序。最终API/用户/设置/索引合同专项81项通过。

64MiB真实gzip合成：旧首屏解压67,375,616字节，新首屏270,336字节；本机9.246ms降至0.148ms。五次重叠/回看读取累计仅解压786,432字节。基准使用可重复的合成正文、临时目录并自动清理；数据只说明算法开销改善，不代表公司磁盘/NFS延迟或生产容量。

归档读取独立审查未发现阻塞问题。冷读gzip包中靠后成员或跳到远处仍须解压前缀；超出512KiB尾部或浏览器8段窗口的回看可能重新定位。缓存不持久化，不改变权威文件、校验发布或保留策略。空闲最多128个句柄、64MiB尾部，另有4个在用线程；30秒空闲回收。
