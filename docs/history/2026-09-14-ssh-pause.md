# SSH暂停恢复的协议侧验收

基线：39d3595。2026-09-14核实该提交CI34843428794七项成功。持续目标保留原有模块化、操作审计、五连接名额、保活、十秒无日志恢复、暂停及日志完整性要求；本轮只补已有暂停实现的协议侧证据。

## 验证范围

`tests/test_ssh_device_pause.py`启动随机本地端口的真实AsyncSSH服务，使用生产连接适配器、SshAdmission、SessionRuntime、Worker.pause和schedule_once。四条初始化命令为outputClose、outputOpen、setDebug -m all -l 7 -d 111、prtHardInfo，服务端逐字节接收并复原完整命令。

- 活跃阶段存在本任务SSH名额；首次定时probe到达服务端后暂停。
- 服务端确认shell EOF和底层connection_lost；Worker移除活跃任务，状态PAUSED，原run未结束，端点锁保留，预算attempts为1，SSH名额归零。
- 暂停时显式执行schedule_once，任务保持PAUSED、nodeId为空且无新会话；不以固定等待代替调度路径验证。
- 恢复经调度保留同run并进入PENDING，新SSH会话重新执行四条初始化；后续probe消耗第二次预算，两个会话命令均为SENT。
- 最终两个服务端连接都关闭，任务SSH占位归零；finally关闭本地监听并收敛处理协程。测试只在pytest临时目录及内存模拟数据库运行，不创建实体设备任务或下载副本。
