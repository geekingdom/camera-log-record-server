# 服务令牌审计事务

原创建与撤销接口先改变凭据，再单独记录审计；撤销重试还会重复产生成功状态审计。先增加两项回归并确认旧实现失败，再将状态变更与审计放入同一数据库事务。

`users/service_tokens.py` 复用固定创建 ID 和随机凭据，事务重试不换 token；提交确认丢失仅按固定 ID 和散列只读确认。撤销在事务内检查当前状态，重复撤销不追加成功状态审计，HTTP 请求记录仍记录每次调用。明文仅本次成功响应返回，响应丢失后不能从数据库恢复明文；调用方需从列表确认并撤销不可取回的令牌后重新创建。

本机 `verify_service_token_audit.py` 正式 ASGI 与真实 MongoDB 验证通过：创建审计失败/取消回滚、撤销失败回滚、并发撤销仅一条审计、撤销后权限失效、创建和撤销确认丢失只读恢复。临时库和目录已删除；未使用实体设备或修改真实用户。定向服务令牌和权限 7 项通过。新增源码未加载本机 API。
