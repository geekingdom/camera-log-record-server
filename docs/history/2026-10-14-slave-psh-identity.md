# 2026-10-14 PSH从机实测与身份保护

## 现场复现

35设备当前为PSH，支持从机1和2。使用用户提供的口令，保存于本机忽略且0600权限文件，不写入仓库/服务日志。主机ifconfig含外部IP及192.168.253.165；从机1含192.168.253.164，从机2含192.168.253.166。

生产Collector链路复现：已成功进入从机ASH后，初始化debug得到`ERROR: No parameters, see 'debug -h'`，旧对话仍等待挑战直到超时，再发送Ctrl-C恢复。此固件ASH存在同名debug程序，不能按“命令不存在”唯一识别。

修正后该帮助响应触发当前ls正向确认，只有实际ASH响应才成功，不由错误文本直接确认。主机和设备Telnet尽力初始化语义不变；从机调试失败不发送Ctrl-C，关闭当前会话并由运行时重新完整握手。

独立测试连接复现旧命令的实际回退：从机两次exit后底层SSH仍未EOF，重新确认shell后ifconfig返回主机外部IP及.165。新命令相同场景均捕获结束边界，未交接主机正文。因此主机串入风险有实机依据，但不能据此断言公司所有重连都由同一原因触发。

## 防止回到主机

`dbclient ...; exit`可能只退出主机PSH启动的嵌套ASH，不能保证外层SSH关闭。新引导在dbclient退出后输出会话随机控制字节标记，唯一接收器跨包识别，保留标记前从机字节，截断标记及其后主机输出，拒绝后续命令并结束读取。

每次新建ShellBootstrap均创建新PSH对话和随机标记，主机状态不继承到从机；重新执行目标登录、ASH及本次ifconfig。验证同时要求目标IP存在且外部主机IP不存在，Collector接受时核对sshTarget。SSH保活只证明外层transport可达，不作为内层身份成功依据。实机两轮从机1/2独立连接均重新请求相应PSH口令、地址验证成功，退出内层会话后均捕获结束边界。

Mock主机保持旧`SSH:IP:端口`键；从机使用追加`:SLAVE_1/2/3`键，不回退主机口令。HTTP解密接口契约不变。

## HTTP 401后保护重连

海康资源的HTTP认证失败写入固定大小的authRejectedAt锁存。现有SSH和设备Telnet连接持续输出时继续保留；断线或无输出关闭后，每次新建连接前复核资源锁存及运行归属，锁存存在则只等待认证变化，不向设备反复提交登录。之后探测变成ERROR/OFFLINE也不能解锁，周期或手动认证成功、已验证成功的凭据编辑才清除锁存。

成功认证只恢复具有系统健康停止标记的任务，兼容旧版本只有AUTH_FAILED任务标记、资源已转ERROR的记录；用户主动停止/暂停不复活。Telnet串口不经过此门控。从机正常EOF也使用固定10秒重连间隔，避免内层退出后立即重复登录。

门控使用已有资源/任务id索引，没有新增历史集合或逐次增长的字段。数据库快照限定2秒，查询失败保守等待。该保护不禁止正常的定时HTTP认证探测，也不能保证设备不会因其它客户端的错误登录被锁定。

真实Mongo副本集/API/Worker/回环SSH验收`verify_isapi_log_independence.py --isapi-test-port 18089 --auth-reconnect-latch`通过：401后COLLECTING且字节增加，强制断线后无新登录，500后仍锁存，200后自动第二会话；再次401且用户停止后成功认证不产生第三会话。脚本加入CI；随机数据库、专属日志目录及临时Mongo容器已清理。前端190项与生产构建通过，无前端行为改动。

实测结束后已移除本轮两份临时debug口令文件，既有设备配置未修改；归档/日志正文均未写入仓库。公司HTTP解密服务在本机不可达，本轮只证明同一生产对话链路使用按目标区分的mock口令能够完成握手，不把它表述为公司接口端到端实测。

## 内存缺项与显示精度

后端采样保持稀疏数据：未发现或无法解析的进程不产生值，实际VmRSS为0仍保存0。前端原有时间线已使用null断点；原悬停格式化中的Number(null)却将缺失显示成0MB，摘要还会跳过末尾空点而显示历史旧值。本轮在格式化入口区分缺失/非有限值与真实0，缺失显示“暂无数据”，末尾缺失不再用旧采样冒充当前值；保留断线及其他指标正常渲染。内存刻度/提示/摘要最多两位小数，原始存储与CSV精度不改，无需迁移旧数据。
