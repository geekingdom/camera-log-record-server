# 通用节点性能预算验证记录

## 范围与实现

本轮面向异构节点，不为单台503GB服务器设置固定配置。专用采集写线程、复用索引句柄、有界字节预留、事件唤醒背压、逐节点AUTO/MANUAL预算、cgroup v1/v2祖先限制与压力恢复已接入Worker和管理页面。管理员准入阈值不自动放大；不引入Redis/Kafka，不扩大fsync间隔。

控制器连续3个高压样本后调低后台读取，只有CPU/内存压力才同时调低写并发；两次调整至少30秒，CPU和内存均有效且连续稳定60秒后小步恢复。批量与等待阈值保留管理员热配置，不进行磁盘跑分或盲目自调批量。

## 确定性验证

- 写线程隔离：阻塞默认线程池后，专用采集写盘仍完成；取消等待实际线程结束，不重复写入。
- 缓冲：释放、扩容唤醒等待者，缩容不丢弃已收字节，取消不泄漏预留；移除每连接10ms轮询。
- 压缩：限速字节包含索引摘要、原文摘要、打包复制和归档正文复核；停止压缩等待实际池关闭后才清除引用。
- 资源：cgroup v1/v2父级配额、复合controller、亲和性、宿主可用内存；有限内存上限但用量不可读时不假定为空闲。
- 配置：真实运行时函数验证保存策略落到缓冲、写并发和读取限速；未知/过期遥测阻断新任务，已有采集不由性能控制器停止。
- 排序：缓冲压力参与候选成本；归档超5分钟告警，不将告警直接等同连接失败。
- 前端172项、TypeScript检查和构建通过；节点策略POST/PATCH、重新编辑回填、有效预算展示、1440/390页面和打开弹窗均通过Playwright，并检查截图。

首次全量回归暴露7项旧测试使用未知遥测仍要求准入，改为显式提供已知资源fixture；第二轮1634项通过、2项失败，原因是debug连接替身未接受`read(size)`参数，已按正式连接合同修复，相关19项通过。最终全量结果以总表收尾记录为准，不把中间失败隐去。

## 合成完整性与边界

2026-09-20最后一次500路短测：每路1200行/秒、256字节/行、输入1秒。600000行、153600000原始字节，源输入1.001秒，含排空与归档共6.370秒；存储正文含时间前缀166800000字节。500个小时包逐路SHA-256与源相同，时间前缀及包内仅日志成员校验通过，结束预留字节为0。父进程峰值RSS为286834688字节，包含合成源与验证器且不含压缩子进程，不能解释为Worker生产RSS。

该合成数据重复率高，压缩后2284038字节不能用于承诺真实设备压缩率。输入源在内存排队，1秒输入后的排空不是持续600000行/秒能力证明；未测文件可读P99，未与旧实现做等条件端到端延迟对比。4KiB接收块降低单会话最坏预留，但相比旧64KiB块增加索引条目与调度频率，目标持续混合负载仍需验收。

本轮目录`.local/collector-performance-final-500`只含本脚本模拟数据，所有Collector关闭、摘要通过且预留归零后已删除；未删除真实日志或修改全局保留期。此前同轮32路/500路短测目录由执行者收尾清理，仅保留报告。

## 后续验收

Linux物理多节点、共享磁盘与其他项目竞争、压缩/检索/多人下载混合长跑、24小时500路完整性与文件可读P99仍待目标环境验收。性能策略是有边界的资源控制，不是自动判断硬盘最佳队深；持续超负载且设备无重放能力时不能承诺源端永不丢失。
