# 真实协议空闲重连验收

本轮从 `8b99fd4` 继续目标 5、6、7、8 的连接生命周期验收。生产连接与运行时逻辑保持不变，新增证据使用本地真实协议服务，不能推断为实体设备或多节点验收。

## 验证对象

- `tests/test_telnet_runtime_reconnect.py` 参数化覆盖 Telnet 设备账号登录和无需账号的 Telnet 串口。
- `tests/test_ssh_runtime_reconnect.py` 使用本地 AsyncSSH 服务端、生产 SSH 连接和 SessionRuntime。
- 初始化配置使用四条独立有序命令：`outputClose`、`outputOpen`、`setDebug -m all -l 7 -d 111`、`prtHardInfo`；每条发送后延迟 0.3 秒。
- 服务端不产生设备日志正文，双方协议保活仍可交互。测试将客户端保活间隔设为 0.2 秒，生产默认值不变；十秒无正文阈值保持真实时间，不通过加速时钟替代。
- 旧连接完成关闭后才发起新连接；每会话初始化顺序、定时预算和最终连接释放分别核对。

## 已取得证据

Telnet 两个参数场景通过（2 passed，37.99 秒）：服务端收到两会话 NOP；设备模式两次登录，串口模式无登录；每会话按精确顺序收到四条初始化命令及一次定时 `probe`；同运行预算累计两次、会话不同；最终两个服务端连接均收到 EOF。

SSH 单项通过（1 passed，19.34 秒）：两次真实密码认证与两个会话的协议保活均由服务端观察；生产连接 ready 至首个 `IDLE_TIMEOUT` 为9.99到13秒之间；旧客户端关闭完成后才创建第二连接；每个会话的四条初始化与定时命令均从真实服务端 stdin 累积验证，不以客户端写入意图代替对端接收。两条定时执行来自同一运行的不同会话，预算和尝试号累计至2；最终两个服务端连接关闭，处理协程显式回收。

审查后增加最后正文至 `IDLE_TIMEOUT` 的 `9.99 <= elapsed < 13` 秒断言，避免把连接建立耗时或整体测试耗时当作空闲计时，也避免十五秒默认值回归仍通过。三秒上界余量用于调度，不改变生产十秒阈值。第二会话初始化等待放宽至五秒，避免把无关 CI 调度延迟误认为恢复失败。

上一提交 `8b99fd4` 的 CI34839232715 已核实七项成功。前端154项与构建通过；导航12项证明既有刷新调度已合并，App当前500行，总表移除了已经失效的重复加载待办。

最终全量后端1380项通过（156.26秒）；前端154项、生产构建、Ruff和差异空白检查通过。生产代码未修改，因此本轮不重启本机服务、不重复35实机重启和已有浏览器布局实验。新提交CI仍须按实际运行核对。

## 证据边界与清理

- MongoMock 仅用于持久化回调及预算状态断言，不能证明数据库事务原子性；真实副本集事务证据另见既有验证脚本及文档。
- 本地真实 TCP/SSH/Telnet 服务不能证明物理设备业务命令成功、真实串口协商差异、长期网络背压、多节点物理隔离或五连接硬件限制。
- 加速保活仅证明协议控制帧不延长日志空闲计时，不证明生产15秒SSH和30秒Telnet默认节奏的持续实测。
- 独立审查指出SSH测试沿用既有保活测试的AsyncSSH私有处理钩子。本机2.24.0已验证；该钩子仅供测试观测，不属于生产逻辑。暂不为测试收紧整个生产依赖范围，升级AsyncSSH时必须复核此钩子与已有 `test_ssh_keepalive_idle_timeout.py` 的兼容性；私有API变化可能导致测试失败，不应因此关闭保活断言。
- 本轮没有连接34/35或串口服务器，没有新建平台真实采集任务。服务端使用随机回环端口，测试在 `finally` 关闭连接和监听器；文件仅写入 pytest 临时目录，不写入本机正式日志根目录。
- 本文是实验记录；未完成项及下一步仍以 `docs/implementation-status.md` 为准。
