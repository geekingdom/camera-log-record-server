# NFS、Coredump 与资源认证集成验证

本记录保存本机阶段验证，不替代当前状态总表。未连接真实设备、未安装本机 NFS、未修改目标 Linux 服务器。

## 下载链路

`scripts/verify_coredump_streaming.py` 使用随机 Mongo 数据库、临时目录和两台隔离环回 HTTP 服务，经过正式 API 代理及节点文件路由。

- 单文件 2,147,483,648 字节；两个客户端同时完整下载，分别约 81.99 和 82.01 秒，字节数与 SHA-256 均一致。
- 8 个并发尾部 Range 请求通过；If-Range 匹配、无效 Range、仅依赖路径 Cookie 的浏览器下载通过。
- 该次验证进程峰值 RSS 113,311,744 字节（macOS ru_maxrss），约 108 MiB；API、节点与客户端在同一进程，因此不是独立服务 RSS 指标。
- 后续 4 MiB 定向复验确认 API 透传 416 的 `Content-Range`。
- 随机数据库、2 GiB 稀疏文件和临时服务日志均已清理。

这证明对应本机 HTTP 场景以有界内存传输，不证明实际 NFS 多设备写入、跨节点链路或生产多人长期容量。

## 文件导出

`scripts/verify_coredump_export_workflow.py` 经主代理独立运行：两台模拟资源的本地目录扫描、固定副本、单文件摘要、多文件 ZIP 成员与正文、取消配额释放和目录记录消失后的清理均通过。使用真实 Mongo 副本集的随机库，所有模拟文件与库在 finally 清理。

## 资源控制

`scripts/verify_resource_health_transactions.py` 经主代理独立运行：已授权的系统停止恢复与用户 STOP 并发，最终任务 STOPPED、恢复标记被清除。该脚本只覆盖这一竞争，不代表全生命周期的所有并发交错。

`scripts/verify_coredump_transactions.py` 经主代理独立运行：Mongo validator 拒绝快照 claim 写入时，总额度预留同步回滚；快照重复释放、导出并发预留与重复释放、取消先提交时没有成功审计均通过。随机验证库和临时目录已删除。
