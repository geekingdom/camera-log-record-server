# 手动命令并发准入与领取

基线 `c942e64`。本轮推进 R10，保留设备连接生命周期、逐路完整性和全项目验收要求。

## 发现与修复

原 API 的独立 count/insert 不能阻止并发请求超出 100 条队列上限。新准入事务先对同一任务声明版本产生写冲突，再计数和插入固定 ID 命令；旧会话独立计数，任务变化返回 409，满队列返回 429。

独立审查随后发现运行时任务归属检查和命令领取分离。新领取事务将两者绑定，且在采集器排队发送前增加会话守卫。守卫在 PSH 恢复前及业务写入前执行，独立于定时预算。未知提交不发送、不重复领取，异常记录仅含任务/命令身份。

## 证据

`scripts/verify_manual_admission.py` 已在真实随机 MongoDB 副本集库运行通过：110 并发恰好 100 成功和 10 次 429、旧会话及任务隔离、过期快照拒绝、插入后取消回滚、领取期间停止冲突、领取后取消回滚、真实提交后模拟确认丢失。临时库在 finally 删除，不创建真实设备连接或日志。

正式 API 回归在路由首次读取后注入重连，确认 409 且无旧会话命令；采集器测试使用实际唯一发送队列，在前一条命令阻塞期间变更归属，确认后续业务命令没有写入。

最终本地后端 610 项测试通过，前端 32 项测试及构建、Ruff 和 diff 检查通过。真实副本集脚本由主代理再次执行，全部条件通过。新增 CI 步骤触发了旧部署测试的固定命令数量断言，已改为逐条检查环境文件/项目名参数，15 项部署回归通过后重新完成全量测试。Linux 结果以本次提交的 CI 为准，不复用基线结果。

## 边界

没有重启真实采集 Worker、没有向设备发出命令。当前运行中的旧 Worker 尚未应用新领取逻辑，受控部署需确认旧连接释放。数据库检查至 socket 写入的最终窗口仍依赖接管隔离，不能用数据库事务宣称设备执行 exactly-once。通用业务审计原子性及全天容量验收仍未完成。
