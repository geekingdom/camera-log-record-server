# Shell 自动登出保活验证

## 背景

设备持续输出日志时，SSH 传输层的 keepalive、TCP keepalive 和 Telnet IAC NOP 都不能视为
交互 shell 输入。设备 shell 仍可能输出 `timed out waiting for input: auto-logout` 后结束，导致
采集运行进入既有断线恢复流程。

## 实现

- `Collector` 仅对 `SSH`（含已验证从机）与 `TELNET_DEVICE` 在初始化完成后建立会话内保活协程；
  `TELNET_SERIAL` 不生成任何无请求输入。
- 每次既有发送队列实际写入普通 shell 命令后记录单调时间。距该时刻满 60 秒才进入保活，正常初始化、
  手动、定时及资源监控命令都会抑制重复保活。
- 保活命令为 POSIX shell 内建空操作 `:`，通过同一个 `CommandDispatcher`、同一连接和同一接收器发送；
  不创建 SSH/Telnet 连接，不读取正文，不占定时命令预算。
- 发送前和发送队列取出时均检查 PSH 命令通道是否确认。调试、从机身份切换或恢复未确认时跳过保活；
  阻塞状态、连接关闭窗口、队列发送异常及未知入队异常都以一秒退避，避免计时已到期时的零等待忙循环。
- 保活调度放在独立的 `collection/shell_keepalive.py`，采集器只保留生命周期与队列边界；发送 guard 还会
  重查最近一次普通 shell 写入，防止保活排队期间已有普通或监控命令写入后再额外发送 `:`。
- 停止和读协程收尾取消并等待保活协程，关闭后不会遗留排队输入。

## 验证

- 本地真实 AsyncSSH 设备模拟器持续输出正文，并在 500ms 没有 shell 输入时输出自动登出文本并关闭。
  将应用保活缩短为 50ms 后，普通命令阶段没有额外 `:`；普通命令停止后收到 `:`，持续超过 650ms
  （超过模拟器自动登出阈值）连接仍保持打开。
- 协议范围回归确认 SSH 从机和 Telnet 设备可建立保活任务，Telnet 串口不会建立。
- 停止真实会话后保活任务为空；队列、调试、从机身份和取消相关既有回归一并通过。
- 不可发送状态和连续入队异常各三轮均验证会执行有限退避；低优先级保活与普通命令发生队列竞态时，普通命令
  先写入会使过期保活在发送 guard 被跳过。

## 限制

本次仅验证本机 AsyncSSH 模拟 shell，不连接或修改实体设备。60 秒为应用层 shell 输入周期；它不改变
已有 SSH 协议 keepalive、TCP keepalive、Telnet IAC NOP 或十秒无设备正文的采集存活判断。

## 全量与审查

保活与资源看板整合后的后端全量测试1888项通过（200.70秒）；后续缓存生命周期补充另行定向验证。只读复核确认主机PSH安全恢复、从机失败关闭及暂停恢复沿用原生命周期。debug专用握手不计入普通命令计时，因此debug成功后可能追加一次安全空操作；不穿插握手，也不额外建立连接。
