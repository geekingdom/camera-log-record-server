# 独立文件可见性探针

## 目的和范围

原有 HTTP 内容接口观测包含源端发送、网络、目录查询和 HTTP 轮询，不等于文件可读延迟。新增 `scripts/benchmark_file_visibility.py` 使用真实 Collector/HourlyWriter 和独立 spawn 读进程，起点为 Collector 的 `last_received_monotonic`，终点为读进程读取到完整行时的同机单调时钟。

观察器先完成首次目录扫描并报告 ready，之后才启动采集输入；不借助 on_log 回调发现数据。每 5ms 扫描探针专用目录，源按 100ms 窗口输入，每条模拟行单独一次 read，32～2048 字节。此条件不能代表任意网络合包或拆包；这是短时诊断工具，不是全天容量发生器。

每路正文、顺序、前缀和全部样本都需校验。收齐后先请求最终扫描，确认无额外完整行或半行，再关闭连接并校验归档正文 SHA-256。缺失、重复、乱序、未知正文、负延迟、观察器退出或超时均失败。输入上限为 200000 条且不超过 64MiB，IPC 有界。

报告的可见性是本机页缓存中完整日志行可读，不证明 fsync 持久化、跨主机/NFS 可见性、API 响应或浏览器实时性。轮询、目录扫描和观察器调度开销包含在测量中，P99 使用完整样本最近秩，不丢弃慢样本。

## 实验与修正

首次 1 路 × 1200 行/秒 × 2 秒、256 字节正文测试收齐 2400 行，P99=212.348ms，但缺少读进程 ready 握手，观察器启动耗时混入首批样本。加入握手后，同配置得到 P99=106.852ms、最大107.155ms、实际1199.92行/秒，两次完整性均通过。首次结果不能据此认定生产写盘超标。

8 路 × 1200 行/秒 × 2 秒收齐19200行，实际9598.98行/秒，P99=2403.944ms、最大2421.735ms。该版本父进程每行执行一次线程切换取 IPC 消息，有明显观测开销风险，后续改为有界批量消费再对照；不能将该结果直接归因于磁盘，也不能隐去未达标样本。

将父进程 IPC 消费改为每批最多256条、保留原观察时间并校验同批全部消息后，同样8路/1200/2秒/256字节得到19200个有效样本、实际9594.8行/秒、P50=47.9ms、P95=107.164ms、P99=114.645ms、最大115.627ms。每路实时正文与归档SHA相同，`verified=true`、`cleanupVerified=true`。这一对照只修改观测工具，证明逐行线程切换显著影响此前观测，不是生产写盘优化幅度。

独立审查在上述明确范围内未发现错误通过或挂死的阻断问题。20项专项测试覆盖真实spawn读取、异常取消清理、正文校验、尾部残余、分卷拼接、IPC批量上限和同批完成之后仍检查额外行。所有 `.local/file-visibility-*` 实验目录均已清理；仅保留本报告，不保留合成日志正文。

最终全量后端1668项通过（175.74秒），前端172项、类型检查和生产构建、全仓Ruff及diff检查通过。CodeGraph已在修改前同步并检查Collector影响范围，完成后更新新脚本与测试索引。本轮不改生产采集链路或前端UI，不新增Mongo集合，不触碰真实设备；CI应以本轮提交SHA独立核验。

所有实验使用专用 mkdtemp 子目录。关闭读进程和 Collector 后删除该目录，失败清理须明确报告；不访问 Mongo、不连接实体设备、不删除真实设备日志。专项测试覆盖取消时保留无关文件、跨分卷半行、尾部额外行、尾部半行、乱序和完整真实 spawn 链路。
