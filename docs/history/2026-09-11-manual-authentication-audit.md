# 手动认证历史与审计原子提交

代码起点：986af5c。对应整体要求：每次用户操作及异常可追溯，后端沿用公共事务模块。

## 问题与实现

已有资源的手动认证原先分别保存认证历史和审计，后一次写入失败可能留下不成对的记录。现在设备HTTP认证在事务外执行一次，确定结果后通过audited_mutation，在同一Mongo事务中更新authentication_records、authentication_record_heads及audit。成功、凭据拒绝和设备离线均使用该路径。权限、所有者和固定资源地址检查仍在访问设备之前。

数据库写入失败通过公共处理返回503；结果保存成功时保留原设备认证HTTP状态。事务回调重试不会重复设备HTTP认证。提交结果未知时不能断言回滚；客户端主动重发是新认证请求，当前没有跨请求幂等去重。
