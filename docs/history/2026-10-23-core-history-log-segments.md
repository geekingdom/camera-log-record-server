# Core 历史连续性与可配置日志分片

## 实现与兼容

海康设备以同 IP、型号和子序列号重新认证添加时，在资源创建事务内关联已软删匹配资源的 Core 目录。目录文件 ID、首次发现时间、已记录的发现事件标志保持不变，既有公开下载地址继续兼容。资源列表及看板使用更新后的目录归属，无额外重复统计。批量创建及手动重新认证采用相同关联逻辑。

新 Core 保存内部设备身份快照；身份不完整或不一致不关联。旧目录无快照时只能依赖软删资源的完整身份进行兼容匹配，无法重建旧版本未记录的物理设备替换历史。既有重复目录不擅自删除。首次目录登记使用资源事务写栅栏，与软删除竞争，避免旧扫描在重添后插入旧归属记录；公开响应剔除栅栏字段。

平台增加 `logSegmentMiB`：默认 10，范围 10–100，步长 5，严格整数验证；旧配置缺失/损坏时安全回退，PATCH 省略字段不重置。配置界面位于日志保存天数下方，API 请求响应模型及生成文档同步中文字段说明。

Worker 启动先加载配置，后台每秒刷新节点共享缓存。Writer 切片时只读取内存，不在写锁中访问 MongoDB；已有分片按打开时上限收尾，新分片读取最新缓存。数据库不可用期间保留最近有效值。已封存归档和既有下载制品不变，新下载作业启动时固定分片配置，重组与完整包复用检查均使用该值。
