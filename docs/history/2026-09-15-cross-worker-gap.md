# 双 Worker 真实内容补读验证

用户确认暂时没有目标 Linux 服务器，继续完善本机可验证部分。本轮基于 `ee6b42d`，仅增加集成验证脚本和 CI，不修改采集、日志读取或前端运行逻辑。

## 实际场景

`scripts/verify_cross_worker_gap.py` 在随机本机 MongoDB 库中启动两个独立 Worker 进程和一个 API 进程。两个 Worker 使用各自临时日志根；生产 `HourlyWriter` 写入三段各 70 KiB 的确定性内容，目录登记为同一任务、三个会话、A/B/A 三个节点片段。目录由脚本登记，并非通过真实设备采集迁移生成。

正式缺口目录接口以 `limit=1` 分页，首偏移为 17，末片段结束于文件长度减 19；正式内容接口每次最多读取 4 KiB。逐次检查非空返回、请求上限、字节终点及 `nextOffset`，最后比较拼接内容和 SHA-256。

主代理复验结果：

- 读取 215,004 字节，摘要 `8824cccb2e9bce1a2ba021b74686b2df6a61fc17ac095159dc5a867955608d9a`，顺序与预期一致。
- 将短游标用于另一任务返回 422，这是游标归属校验，不是资源读取权限拒绝。
- 中间文件标记删除后，缺口目录明确返回 `FILE_UNAVAILABLE`。
- 中间文件恢复 READY 并确认内容读取 200，然后实际停止 Worker B 并确认退出；B 文件读取返回 503，A 文件仍返回 200。
- 关闭所有写入器及本轮进程，随机数据库与临时目录回收完成；没有访问实体设备或主平台日志。
- Ruff 全工程检查、工作区 diff 检查及 CI YAML 解析通过。新增 Linux CI 作业启动仅回环地址可达的临时 MongoDB 副本集，运行同一脚本并始终回收容器。

## 审查修正与边界

初稿在文件已经 DELETED 后修改节点地址，以 503 判断节点不可达，无法排除文件删除造成的假阳性。最终改为恢复文件可读、实际终止节点进程并验证另一节点仍可读。初稿重复填充长度不足 70 KiB 的问题也已修正，最终以实际返回字节与摘要为证据。

脚本最终报告 `migrationClaim=false`。该结果证明两个真实 Worker 的本地存储与正式 HTTP 补读集成，不证明 SSH/Telnet 采集迁移、物理服务器网络分区、磁盘断电或 500 路持续容量。主机间时钟偏差、故障接管及目标部署验收继续保留。
