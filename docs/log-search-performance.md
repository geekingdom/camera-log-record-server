# 历史日志检索性能与准确性合同

## 目标

检索面向故障排查：尽快返回第一批已确认匹配，持续显示扫描进度，并能从匹配行打开原始上下文。完成状态、部分结果、截断和失败必须可区分。性能优化不能改变关键词的字面匹配语义、时间范围或原始字节位置。

## 当前实现边界

- 创建作业时冻结文件清单和字节水位，时间范围使用接收时间索引的 `[start,end)`，不以设备打印的时间猜测。
- 本地 READY 小时归档复用压缩包读取；连续成员保持同一接收顺序，避免搜索前反复生成压缩快照。OPEN 和远端文件继续使用固定水位快照。
- 匹配仍由原始字节确认。跨读取块、跨连续分卷的关键词和完整逻辑行必须保留；会话或序号中断不得拼接。
- 运行中发布已确认结果前缀。前端状态轮询使用 `includeResults=false`，结果经独立分页接口获取；完成前不能将当前条数当作最终总数。
- 发布结果、完成和取消均服从作业执行归属。失去租约的旧执行器不得覆盖新执行器结果。
- 每节点最多两个读取作业，共享读取带宽预算；取消等待实际文件操作收尾，不提前释放线程、临时目录或并发槽。采集写入和日志保留不受结果显示限制影响。
- 保留现有查询上限：单次24小时、1000项结果、8MiB结果正文。达到上限必须返回 `truncated=true`；不能声称返回了全部命中。单行超过256KiB且命中时明确失败，禁止冒充完整行。

## 验证口径

同一数据集比较旧路径与新路径的完整结果，包括文件ID、命中字节偏移、逻辑行起点及正文。另测跨分卷、中文关键词、时间边界、缺失索引、文件替换、取消和旧执行器写回。

性能报告必须区分：首批结果时间、全部扫描时间、处理字节数、文件数、压缩包打开次数、是否启用读取限速。合成数据需含接近实际的短日志行，不能仅以重复长字符串的压缩吞吐代替业务检索性能。

## 大规模验收边界

已实现小时级持久化全文候选索引：SQLite FTS5 contentless trigram，不保存整行正文；按关键词前三个Unicode字符保守筛选分卷，再由原始字节确认完整关键词、时间和逻辑行。跨分卷关键词和行上下文保留，少于三个字符及特殊控制字符仍走完整扫描。常见词仍可能命中大部分分卷，不承诺任意规模日志的毫秒级查询。

索引位于小时包旁的 `.search.sqlite`，不进入下载压缩包；归档发布时通过隔离压缩进程流式构建，失败不影响原包。旧包每个Worker每轮最多检查64条目录、补建一个小时包，持久游标循环推进。缺失、不支持FTS5、版本/归档指纹不符或损坏均回退原文。索引完整性检查按文件版本缓存最多64项，替换或修改后重新检查。跨Worker通过内部鉴权批量获取候选证据，旧节点无接口时回退，不能将不可用伪装为零命中。

每小时索引最多256MiB，构建前要求至少384MiB空闲，逐成员检查保留128MiB余量；归档保留清理同步删除索引。索引重建采用临时文件、fsync及原子替换，取消需等进程实际收尾。实际空间比例取决于日志词汇分布，不能预先承诺。

用户确认600MB/小时是目前已知单设备最大值，并非普遍水平。严格600,000,000原文字节合成验证中，索引构建12.398秒、体积76,804,096字节；全量约14.81至15.05秒，稀疏/中文/跨段长行候选扫描分别0.505/0.747/2.882秒，无命中不读原包。首次索引完整性检查与查询0.552秒，复查约0.0004秒。候选扫描与索引查询需相加，均不是浏览器端到端延迟；四类结果与完整扫描严格一致。三小时另测可跳过不匹配小时包，不能替代超大范围、多节点、多人及持续采集混合负载验收。
