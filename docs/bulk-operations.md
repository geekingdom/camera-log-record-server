# 列表多选与批量操作

设备资源、采集任务、命令模板列表支持当前页内多选。选择框依据当前登录用户权限和创建者信息决定是否可选；管理员可以操作全部对象。共享模板的使用权不等于删除权。

普通用户默认只展示本人创建的记录，管理员默认展示全部。可切换“查看全部”，开启后使用创建用户筛选；模板的“全部”仍仅包含自己可见的个人、定向共享和全局共享模板。创建时间、删除时间使用北京时间，任务页面的删除时间明确表示所属资源删除时间，任务记录与日志仍保留。

| 页面 | 批量操作 | 适用对象 |
| --- | --- | --- |
| 设备资源 | 删除 | 未删除且有资源写入、任务控制权限的本人资源或管理员可管理资源 |
| 采集任务 | 启动、停止、暂停、恢复 | 有任务控制权限的本人任务或管理员可管理任务，具体动作沿用单项状态矩阵；暂停/恢复仅SSH |
| 命令模板 | 删除 | 有模板写权限的本人模板或管理员可管理模板 |

批量操作先展示数量、名称和影响并二次确认。任务混合状态时，仅发送当前动作适用的任务，同时显示跳过数量。资源删除会请求停止关联任务，但只软删除资源，已有日志继续保留；关联他人任务的资源仍由后端拒绝普通用户删除。

每次操作冻结确认时的对象ID及版本，逐项调用原有正式接口，不绕过所有者、版本、来源IP或任务状态校验。请求串行发送且不自动重试；单项失败不阻断其他项目，结果按对象显示已提交、失败或未执行。HTTP202只表示控制意图已接受，任务实际运行结果仍由状态轮询和操作记录确认。

翻页或改变筛选条件会清空旧选择，禁止把看不见的其他页对象加入操作。离开页面或退出登录后，不再启动剩余请求；已提交请求由后端正常执行。编辑名称、连接参数及模板命令仍使用单对象表单，避免把不同设备配置误覆盖成同一份。

批量处理不会新增一套授权逻辑。第三方如需批处理，也可以逐项调用相同接口，保留每项结果和对应请求ID；不能将一项失败等同于全批回滚。
## 模板删除与历史

命令模板删除采用软删除：成功请求会写入 `deletedAt` 并递增版本，默认列表、详情和任务引用均不再读取该模板；已保存到任务的命令快照不受影响。创建者和管理员可通过 `includeDeleted=true` 查询历史，普通用户仅能取得自己的已删除记录，仍不可借此读取他人的私有模板。

模板名称唯一约束保持为 `(createdBy, name)`，软删除记录仍占用该创建者的名称。因此删除后不能以相同名称新建模板；需要继续使用时请新建不同名称的模板。
