# 验证记录

本页仅记录已实际执行的验证和其边界，不能替代生产容量验收。

## 真实设备会话

已使用两台真实设备完成两轮 SSH pause/resume 验证。每轮 pause 后等待 12 秒；记录结果为 `release=0`、`resume=1`。恢复后保持同一 `runId`，同时创建新的 `sessionId`，符合暂停释放会话、恢复重新建连的预期。

## 自动化测试基线

此结果包含每秒同步和单独压缩进程，RSS 不含压缩子进程。复现命令为 `python scripts/benchmark_collector.py --routes 500 --seconds 5 --output .local/new-benchmark`。

本次记录时后端测试为 83 项通过，前端测试为 8 项通过，Ruff 与前端类型检查及生产构建通过。构建仍提示主包超过 500 kB。浏览器验收覆盖模板填充、任务表单、实际时间戳日志、本地视图暂停继续与清空、移动端和原生下载，控制台异常为 0。此前 4 个真实 WebSocket 订阅合计接收 80 帧，协议错误、偏移错误及实时缺口均为 0。

新增回归覆盖：没有 `retainUntil` 的过期归档清理；保留近期、远端、被作业引用及下载保护的文件；候选扫描后新增下载保护的删除竞争；已发布归档恢复 OPEN 目录项；拒绝摘要错误和会话身份不匹配；不恢复 DELETING 文件；一路停止失败仍关闭其他设备连接。测试使用隔离临时目录和模拟数据库，没有对真实设备日志执行过期删除。

删除声明后的崩溃恢复另外覆盖文件尚存、文件已删除及远端 DELETING 记录：只续做本节点的删除，文件操作和目录删除均可重试。

请求日志新增六个测试场景：完整流结束才记录、响应头之前异常、响应头之后异常、取消传播、底层发送失败不累计未确认字节、401/422 响应保持状态与关联 ID。真机两个完整下载分别为 2,235,505 和 1,004,607 字节，运行日志的 `responseBytes` 与客户端接收大小一致；两次 Range 请求均为 206、100 字节且 `responseComplete=true`。浏览器流程再次通过，桌面和移动端截图已检查。

Telnet 保活增加真实 `telnetlib3` 与本地 TCP 服务测试，直接检查线上 `FF F1` 控制字节而非仅模拟 writer。验证保活后仍可收日志、发送命令，正文 `FF FF` 正确还原为单个 `FF`，主动关闭终止心跳并释放对端连接。对端持续发送 NOP 的情况下，采集器仍在默认十秒无正文时触发 IDLE_TIMEOUT；没有把保活保存为日志。本机库版本为 telnetlib3 2.6.1；Telnet 设备直连的硬件兼容性仍待验证。

新增实体串口服务器的 10002、10003 两个端口已按 TELNET_SERIAL 完成联调，账号密码留空，配置四条有序初始化命令。两路均收到实际打印，手动命令状态 SENT，停止操作成功，归档下载及 Range 206 通过；停止后端口连接数均为零，原有两台 SSH 各保持一条连接。注册脚本曾因只用 IP 构造幂等键发生第二端口冲突，现改为协议、IP、端口共同标识，并增加同服务器多端口回归测试。

尚未执行多台 Linux 节点上 500 路持续 24 小时的端到端验收，也未证明 P99 文件可读延迟不超过 200 ms。本机应用镜像构建在 Docker Hub 的 Python、Node、Nginx 基础镜像元数据请求阶段超时；完整容器链路改由 GitHub Actions 的 `container-smoke` 作业在隔离 Linux runner 上执行，具体通过状态以对应提交的作业结果为准，不能把本机直接启动结果当作应用容器验收。

## Docker 与副本集验证

容器验收配置生成新增两项测试：使用独立随机令牌及合法 Fernet 密钥、POSIX 文件权限为0600；已有配置文件拒绝覆盖。CI 不使用两台真实设备或开发环境凭据。

验收器自身的五项回归覆盖归档摘要损坏拒绝、ZIP 条目乱序按清单顺序重组、跨片段半行、实时偏移缺口、合法轮转与半行等待、时间前缀格式。`verify_container_service.py` 已通过本机前端代理试跑：两个初始化命令有序到达，十六行合成日志完成实时与归档比对，手动命令实际到达并返回 SENT，停止释放连接，下载及 Range 206 通过。该本机结果用于验证脚本，Docker 镜像链路仍由 CI 独立执行。

Docker 引擎可用。本轮用已有官方 MongoDB 7 镜像（摘要 `sha256:43fddee7e532a920f3dfdee9e8f4834398c155c26bcb92d790cc1cd3c630fc40`）在独立 `camera-log-acceptance` 项目完成三成员全新卷冷启动：初始化作业仅在一主两从健康后成功退出。重复运行初始化不重建拓扑；使用 `w=majority,j=true` 写入验证记录，三个成员重启后仍可读取。测试项目及其临时卷已清理，未使用现有开发数据库。

`node --test tests/deploy/test_mongo_init.mjs` 四项通过，覆盖首次选主等待、重复初始化、非94错误传播、成员不齐超时。Compose 解析确认默认 worker 使用稳定 ID、可通过服务名解析的 URL 和命名卷；生产 worker 配置要求显式提供节点 ID/URL。新空命名卷的目录权限复制已用独立卷验证，宿主 bind mount 仍需预先授权。
