# 设备资源级监控

本次新增需求将 Coredump 和 CPU/内存监控配置归属设备资源；任务继续负责日志连接，监控复用正在采集的 SSH 或 Telnet 设备连接。本文定义接口和验收目标，实现完成度以 `implementation-status.md` 为准。

## 配置与生命周期

海康网络资源增加 `enableCoredumpMonitor`、`enableResourceMonitor`，默认均为 false。串口服务器不支持开启。任务表单和任务写入接口不再接受 Coredump 开关；资源创建者或管理员通过资源编辑及二次确认修改开关。

只有资源未删除、认证 ONLINE，且有 `COLLECTING + RUNNING` 的 SSH/TELNET_DEVICE 任务时执行监控。两个功能分别竞争资源级租约，不额外建立设备连接。任务暂停、停止、重连时取消旧会话采样；过期回调不得写入新会话。没有合适任务时保持配置但不挂载、不采样。

Coredump 的负责人退出时，如仍有同资源的合适采集任务，仅移交控制，不卸载。最后一个任务停止或暂停、资源关闭开关或认证失效时，尽力通过原连接 `umount -l`；设备离线不能承诺卸载成功，须保留明确状态。接管者沿用资源已登记的 NFS target 和来源节点，避免不同 Worker 路径导致无意改挂；原来源 Worker 继续扫描文件。首次挂载才按当前节点配置创建设备 IP 子目录。

CPU/内存监控每60秒采样，优先级低于人工命令。先确认 ASH；35设备默认ASH，正常探测后不发送debug。无法确认模式或采样失败，只记录本轮失败，不阻断日志。设备正文仍从唯一接收器进入正常日志链路，监控采用带随机结束标记的有界旁路响应捕获，不能建立第二接收器。

可选监控装配在独立的会话监督协程中进行。Coredump来源查询或状态登记失败，仅记录运行日志并在5秒后重试，不触发日志连接重建，也不阻止CPU监控启动。无本地NFS配置的节点可以等待其他节点登记资源来源后接入监控；没有真实来源时不构造环回挂载地址。每次查询前后核验原采集器，关闭时先取消装配和采样，再使用原连接完成NFS卸载并释放租约。

每个指标命令、进程发现、进程匹配规则和单个PID状态分别隔离失败，已取得的值保留并继续其他项。部分成功记录PARTIAL及errors中的具体scope/code，全失败记录FAILED；下一轮重新尝试。任务暂停、连接关闭或失去租约时立即取消，不为继续采样而绕过会话权限。

进程内存对象按匹配后的进程名称识别，PID只用于读取设备`/proc/{pid}/status`。同一轮同名进程的VmRSS合计为一个值，进程重启后PID变化不拆分曲线；历史含PID的数据在趋势和CSV中按名称合并。同一设备身份内连续展示，不跨型号或序列号变化合并。

内存图默认展示原始数值，可切换为比率模式：每条曲线以当前查询范围内首个有效数值为100%，计算`当前值 / 基准值 × 100%`；例如200KB增至250KB显示125%。缺失或失败样本不作为基准，零基准不能计算且明确提示；缩放图表不重新选择基准，改变查询范围或自动刷新会以新范围重新计算。CPU仍展示原CPU指标。

## 默认采样规则

参考 `/Users/geekingdommac/Documents/CPU_Mermory.py` 的命令和解析，未复制其中独立连接、HTML重写或全量日志保存流程。

| 指标 | 命令来源 | 数值与单位 |
| --- | --- | --- |
| MemAvailable | `cat /proc/meminfo` | 第1捕获组，KB |
| Slab | `cat /proc/meminfo` | 第1捕获组，KB |
| CPU idle | `top -bn1` | idle百分比，% |
| Dsp_Main / Davinci / HEOP bll、ipp | `ps`识别进程后 `cat /proc/{pid}/status` | VmRSS，KB；PID必须为正整数 |

后台 `platform-settings.resourceMonitor` 提供指标items（名称、单行命令、数值正则、单位、开关），进程发现命令、进程匹配规则和动态名称捕获组、PID命令模板及VmRSS数值正则。规则保存沿用平台版本CAS及审计；Worker下一轮读取新版本。命令/响应/正则数量和大小有上限，正则执行有超时；不将响应正文存入Mongo。

## 历史与查询

每资源每UTC小时一桶，分钟键保存结构化样本，避免重连在同一分钟无界追加。桶固定过期时间，默认90天，后台允许1至90天；修改期限不延长已有桶。按资源和小时索引查询，TTL清理无恢复依赖的指标桶。设备身份变化需要保留样本所属设备信息，前端不得将不同身份的数据伪装成连续正常趋势。

`GET /api/v1/resources/{id}/resource-metrics` 使用 `tasks:read`，与资源可见范围一致。参数 `start/end` 带时区且为半开区间，默认最近一小时、最多31天，`limit`最多2000，后续使用 `cursor`。返回 `items`，每项包含 `sampledAt`、`status`、`values[{id,name,value,unit,pid?}]` 和安全错误码。只返回结构化值，不回传命令响应或密码。

前端资源行提供入口，每次只展示一个图表，默认内存，通过模式切换查看CPU。提供各项当前数值和变化、图例筛选、最近30分钟/1小时/自定义时间、刷新暂停、CSV导出和采样统计。内存纵轴依据选中的指标和可见时间范围自动计算并留出边距，避免固定大区间掩盖变化。无数据、失败、缺采样必须可区分，不填造零值；CPU使用百分比，内存使用KB并可格式化显示为MB。长范围分页读取有界，超过可视化容量明确提示缩短范围。

## 节点分配

节点默认isGeneralNode=true，可接收所有资源。非通用节点必须提供resourceNetworks，支持多个单IP及IPv4/IPv6 CIDR；依据设备资源IP匹配，不能用Telnet串口连接目标替代。匹配且健康、可接入、有容量的专用节点优先，然后按现有健康与压力排序；专用节点不可用时回退通用节点。配置由后端在分配时读取，Worker不增加地址路由逻辑。配置变化不强制迁移现有运行；最终认领事务再次验证最新节点规则。

## 验收

1. 资源开关默认关闭，保存和回填正确；任务不再提交旧开关；串口不允许启用。
2. 零任务不执行；两个SSH/Telnet设备任务只有一份监控；暂停负责人后接管且不卸载；最后一个暂停才卸载；恢复重新挂载。
3. 资源认证失败、删除、开关关闭、任务重连均取消旧采样；命令失败不影响日志。
4. 捕获分包、背景打印、超时、溢出、模式失败和正则超时；值缺失不当作零；PID输入不可注入。
5. 配置CAS和权限、下一轮生效、小时桶唯一/到期、索引Explain和历史游标边界。
6. 35实机通过正式API建资源任务，采样并核对结果、暂停和恢复后收尾；不额外SSH、不发送kill；临时采集文件及时清理。
7. 桌面和移动浏览器截图、图表非空、缩放图例/时间/导出及无权限状态。
