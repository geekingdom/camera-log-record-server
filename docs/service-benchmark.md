# 正式服务多路协议压测

`scripts/benchmark_service.py` 通过正式资源、任务、小时目录和下载 API 驱动真实 Telnet 或 SSH 模拟源。日志经过 API 调度、采集节点、文件写入、MongoDB 目录登记及小时压缩，最终经下载 API 流式比对源摘要。它补充进程内 `benchmark_collector.py`，不能用两者结果互相替代。

## 本机运行

先启动 API、worker、MongoDB 及前端代理，再执行：

```sh
.venv/bin/python scripts/benchmark_service.py \
  --url http://127.0.0.1:5173 \
  --routes 8 --seconds 36 \
  --realtime-clients-per-route 1 --search-interval 5 \
  --output .local/service-benchmark-8x1200
```

默认每路每秒 1,200 行，每行 256 字节，按 100ms 批次输出；正文包含路由标识和单调序号。36 秒足以跨过 10 MiB 日志分卷边界。输出目录必须不存在，脚本不会覆盖已有报告或日志。令牌从 `.env` 或 `--env-file` 读取，不输出到报告。

压测创建独立合成串口资源，不访问实体设备，不修改节点容量或准入开关。每路完成后等待目录水位覆盖全部源字节，再通过 API 停止并确认连接释放。清理阶段即使个别停止请求失败也会尝试资源软删除，等待 `deletionState=DONE`；失败信息保留在 `cleanup.json`。已采集日志保留，资源软删除不删除归档。

使用 `--protocol SSH` 切换为真实 AsyncSSH 加密传输和合成网络设备资源。工具先启动只读 ISAPI 模拟端，通过 Basic 认证创建资源，使用本轮临时密码和临时主机密钥；这些凭据不写入报告。API 必须能够访问模拟设备 IP 的 80 端口。默认直接监听 80；无低端口绑定权限时，可使用 `--device-info-port 18080` 并由测试环境将设备 IP 的 80 端口转发至该模拟端，测试结束后移除转发。SSH 模式在 API 停止任务后额外等待底层传输关闭，不以 shell 通道关闭代替连接释放。

## 报告判定

- `integrityVerified`：各路所有小时包去除服务器时间前缀后，行数与 SHA-256 等于源端记录；同时检查连续序号、分卷顺序、10 MiB 上限以及包内只有日志文件。
- `targetRateAchieved`：每路实际发送耗时不超过配置时长的 105%，不能只看配置的行速率。
- `concurrentWindowVerified`：所有路由共同发送的重叠窗口至少覆盖配置时长的 95%。路由连接后立即发送，以免等待其他路由时触发 10 秒静默重连；短测若启动偏差过大，会明确失败。
- `cleanupVerified`：没有未确认的停止、资源回收或节点指标采样错误。正常连续输出场景每路只允许一个连接，重连会使验收失败。

`passed` 必须同时满足上述条件。`nodes.jsonl` 按秒记录节点输入速率、活动数、磁盘余量及节点写入延迟；节点延迟不是经 API 查询文件可读的端到端 P99。`tasks.jsonl` 保存本轮创建的任务身份，供异常或强制终止后恢复处理。每小时单独下载，避免整日导出超过单作业 20 GB 上限；校验跨小时、跨分卷保留半行及时间前缀，不把整日正文加载进内存。

## 联合实时订阅

全量观察器在源端连接后读取任务运行 ID，首帧明确携带 `cursor=<runId>:0`。
不带游标的正式实时接口默认只返回最新尾部窗口，不能用于从零开始的完整性验证；
订阅认证与首批数据处理之间积累超过尾部窗口时，也不能据此判定原始日志丢失。

`--realtime-clients-per-route` 默认为 0，范围为 0～4。大于 0 时，每路在发出订阅认证请求后开始源端输出；接口没有独立认证确认帧，认证拒绝或订阅异常会使压测失败。每个观察器以不超过 2 MiB 的 WebSocket 帧上限和有界半行缓冲，验证同会话文件偏移连续、首偏移为零、文件不回跳、源路由和逐行序号连续，并对去除服务器时间前缀后的正文计算摘要。源端发送完成后必须先收齐并验证所有订阅，才停止任务和下载归档。

报告中的 `realtimeClientsPerRoute`、`realtimeFrames` 和 `realtimeLogBytes` 表示订阅规模和总传输量；每路 `realtime` 列出各观察器的正文摘要与行数。只有所有订阅均完成源摘要比对，`realtimeVerified` 才通过。0 模式不执行实时验收，该标志仅表示未启用的可选检查不阻止原归档测试，不能声称实时链路已验证。订阅失败、源失败及取消时都会等待观察器结束，避免遗留后台连接。

该观察器校验完整性，不测量实时推送 P99，也不模拟前端限速展示。它收齐预期行数后结束，不验证此后无限时间内没有额外推送；下载归档仍独立核对全部存储正文。持续并发搜索通过 `--search-interval` 启用。容器 CI 已启用每路一个观察器，联合验证八路采集与实时订阅。

本机联合短测（2026-09-09）使用 8 路、每路 1,200 行/秒、256 字节/行、36 秒，每路一个订阅，完整性、目标发送速率、共同窗口和清理全部通过。共 345,600 行、88,473,600 源字节；实时收到 2,888 帧、96,076,800 个含前缀字节。共同发送窗口 35.972 秒，含下载和清理总耗时 47.373 秒。最终 16 个日志分卷、下载 2,976,832 字节，每个订阅及各路归档均通过源摘要比对。节点采样中的写入延迟最大值为 105 ms，不是 API 文件可读或实时推送 P99。证据保存在本机忽略目录 `.local/service-realtime-final-8x1200/`；真实 34、35 任务保持原运行采集。短测不代表 500 路 24 小时通过，合成日志压缩率不用于真实容量估算。

## 正式内容接口读取延迟

多路持续验证使用 `benchmark_service.py --read-latency`，可与实时订阅、搜索以及 SSH 模式组合。每路从源端开始发送一批到内容 API 返回该批全部完整行计时，按批次行数加权，形成行级可读延迟的保守上界。观察器核对文件和会话身份、字节游标、逐行序号及源摘要，并重组跨小时或分卷的半行。

`readLatencyEnabled` 明确是否启用；启用时只有每路收齐全部行且 `readLatencyVerified=true` 才允许总 `passed=true`，最慢一路的 P99 上界另列 `maxRouteReadP99Ms`。关闭时标志为真仅表示可选检查未启用，不代表可读延迟已验收。每路 `readLatency` 包含行样本数、批次数、文件数、P99 和最大值。

未完成批次最多保留 1,000 项，超过上限明确失败；直方图固定 202 个桶，0～200ms 以 1ms 向上取整，溢出桶保留计数并以实际最大值保守报告百分位。慢样本不会因运行时长增加被淘汰。目录文件身份集合随本次任务分卷数量增长，正文和完整样本序列不会累积在内存中。该模式会实际增加内容 API 读取负载，计时包含查询排队、网络与轮询，不等同于节点内部写入指标。

2026-09-09 本机 8 路 Telnet、1,200 行/秒、256 字节/行、36 秒，同时每路一个实时订阅、每 5 秒搜索及内容 API 观测：345,600 行正文及归档摘要通过，每路 43,200 行、360 批、两个分卷，逐路 P99 上界 155～166ms，最大批次约 252.34ms；32 次搜索、实时和清理通过。报告为 `.local/service-read-latency-loaded/report.json`。这不是 500 路或 24 小时结论，也不表示每批均低于 200ms。

运行 `.venv/bin/python scripts/benchmark_read_latency.py --output .local/read-latency-check`，默认单路每秒 1,200 行、每行 256 字节持续 10 秒。输出目录必须不存在。工具通过真实 Telnet 源和正式内容 API，以 10ms 间隔续读，测量源端开始发送到 API 返回完整行的延迟上界，包含网络、写入和 API 代理耗时。它验证内容 API 正文摘要、行数及归档下载摘要，并清理合成资源。

报告要求所有发送批次被读到、清理成功且 P99 不超过 200ms。短测结果不代表多路持续负载容量；自然小时边界可跨文件续读，单次输入限制在 10 MiB 以下，分卷压力应使用多路压测工具验证。报告和下载正文仅保存在忽略的本地目录中。

本机对照测量采用相同的 10 秒、1,200 行/秒、256 字节配置。优化前 P50 为 546.0ms、P99 为 1,044.9ms；优化后 P50 为 62.3ms、P99 为 122.9ms，最大 130.1ms。两次均收到 100 批、12,000 行并完成归档摘要校验和清理；优化后的观察器额外校验内容 API 正文摘要，结果同源端一致。计时范围相同，但观察器并非完全相同版本，不能将单次对照视为统计稳定性证明。原始证据分别位于本机 `.local/read-latency-before/report.json` 和 `.local/read-latency-after/report.json`。

## 并发搜索

`--search-interval` 为非负整数秒，默认 0 表示关闭。启用后，每路在输出期间串行提交搜索，完成后等待指定间隔；最多一个未完成搜索，避免长测积累无界作业。关键词取自已登记字节水位附近的完整行，校验唯一命中、非截断、路由序号及结果文件属于作业冻结范围。搜索失败立即取消发送，退出时通过正式 DELETE 接口取消尚未确认终态的搜索；取消状态不代表扫描线程已瞬时退出。

报告包含 `searchIntervalSeconds`、`searchCount`、`searchMaxElapsedSeconds` 和 `searchVerified`。启用时每路至少一次搜索成功才允许通过；关闭时 `searchVerified=true` 仅表示可选检查未启用。搜索耗时包括队列等待及扫描，不是单行日志可读延迟。

2026-09-09 本机联合验证使用 8 路、每路 1,200 行/秒、256 字节/行、36 秒，每路一个实时订阅、搜索间隔 5 秒。共 345,600 行、88,473,600 源字节；实时收到 2,888 帧、96,076,800 个含前缀字节，逐路实时及归档摘要一致。33 次搜索全部唯一命中，最长 7.286 秒；共同输出窗口 35.993 秒、含归档下载和清理总耗时 47.633 秒。清理无错误，证据位于忽略目录 `.local/service-search-8x1200/`。该结果只证明本机短时联合链路，不代表 500 路持续容量。

## 集群长测

在独立 Linux 压测机上运行，`--device-host` 必须是所有采集节点可访问的模拟端 IP，`--bind-host` 是压测机监听地址。随机监听端口必须可达；API Token 仅存于本机受限配置文件。先确认采集节点准入和容量足够，再设置 `--routes 500 --seconds 90000`，为启动偏差预留一小时，不要提高本机单节点容量来冒充生产部署。完整日并发要求 `allRoutesOverlapSeconds >= 86400`，报告单独给出 `fullDayConcurrencyVerified`；短测的 95% 重叠容差不能用于宣称满 24 小时通过。

当前工具验证所选 SSH 或 Telnet 串口的持续输出、目录与归档下载链路，并可按配置叠加逐路实时订阅及持续搜索；不覆盖设备真实日志压缩率、物理节点隔离及静默重连正确性。完整设计验收还需要这些场景，并须检查长测过程中的积压是否有界、每路文件可读 P99 是否达标。确定性合成正文的压缩率不能用于实际设备容量规划。

## 当前集群验收缺口

2026-09-09 实际 API 仅报告 `local-dev` 一个节点，容量 100、活动任务 2，剩余准入容量 98；本机日志盘约 994.61 GB，空闲约 602.83 GB。这些是检查时的快照，执行长测前必须重新读取节点和磁盘状态。不能提高本机容量参数或复用高度重复日志的压缩率来声称已具备生产集群条件。

500 路各 1,200 行/秒、每行正文 256 字节时，输入为 153.6 MB/s；加上每行 22 字节时间前缀，存储输入为 166.8 MB/s、每天 14.41152 TB（十进制），七天原始数据约 100.88 TB。容量规划还需压缩临时空间、导出产物与运行余量，真实压缩率须另行测量。

待提供可部署的 Linux 采集节点、独立压测机和配置路径后，按八节点部署基线执行长测。验收须同时保留：每路连续 24 小时源序号及摘要、正式下载校验、逐路文件可读 P99、队列与压缩积压、磁盘余量，以及旧节点实际隔离后接管的基础设施证据。当前已具备小规模 SSH/Telnet 链路证据、负载下逐路可读延迟工具和事务隔离测试，尚不具备上述集群结论。长测启用 `--read-latency`，不能拿节点内部写入指标代替正式内容接口的观测结果。
