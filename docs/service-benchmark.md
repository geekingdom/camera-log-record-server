# 正式服务多路协议压测

`scripts/benchmark_service.py` 通过正式资源、任务、小时目录和下载 API 驱动真实 Telnet 模拟源。日志经过 API 调度、采集节点、文件写入、MongoDB 目录登记及小时压缩，最终经下载 API 流式比对源摘要。它补充进程内 `benchmark_collector.py`，不能用两者结果互相替代。

## 本机运行

先启动 API、worker、MongoDB 及前端代理，再执行：

```sh
.venv/bin/python scripts/benchmark_service.py \
  --url http://127.0.0.1:5173 \
  --routes 8 --seconds 36 \
  --output .local/service-benchmark-8x1200
```

默认每路每秒 1,200 行，每行 256 字节，按 100ms 批次输出；正文包含路由标识和单调序号。36 秒足以跨过 10 MiB 日志分卷边界。输出目录必须不存在，脚本不会覆盖已有报告或日志。令牌从 `.env` 或 `--env-file` 读取，不输出到报告。

压测创建独立合成串口资源，不访问实体设备，不修改节点容量或准入开关。每路完成后等待目录水位覆盖全部源字节，再通过 API 停止并确认连接释放。清理阶段即使个别停止请求失败也会尝试资源软删除，等待 `deletionState=DONE`；失败信息保留在 `cleanup.json`。已采集日志保留，资源软删除不删除归档。

## 报告判定

- `integrityVerified`：各路所有小时包去除服务器时间前缀后，行数与 SHA-256 等于源端记录；同时检查连续序号、分卷顺序、10 MiB 上限以及包内只有日志文件。
- `targetRateAchieved`：每路实际发送耗时不超过配置时长的 105%，不能只看配置的行速率。
- `concurrentWindowVerified`：所有路由共同发送的重叠窗口至少覆盖配置时长的 95%。路由连接后立即发送，以免等待其他路由时触发 10 秒静默重连；短测若启动偏差过大，会明确失败。
- `cleanupVerified`：没有未确认的停止、资源回收或节点指标采样错误。正常连续输出场景每路只允许一个连接，重连会使验收失败。

`passed` 必须同时满足上述条件。`nodes.jsonl` 按秒记录节点输入速率、活动数、磁盘余量及节点写入延迟；节点延迟不是经 API 查询文件可读的端到端 P99。`tasks.jsonl` 保存本轮创建的任务身份，供异常或强制终止后恢复处理。每小时单独下载，避免整日导出超过单作业 20 GB 上限；校验跨小时、跨分卷保留半行及时间前缀，不把整日正文加载进内存。

## 集群长测

在独立 Linux 压测机上运行，`--device-host` 必须是所有采集节点可访问的模拟端 IP，`--bind-host` 是压测机监听地址。随机监听端口必须可达；API Token 仅存于本机受限配置文件。先确认采集节点准入和容量足够，再设置 `--routes 500 --seconds 90000`，为启动偏差预留一小时，不要提高本机单节点容量来冒充生产部署。完整日并发要求 `allRoutesOverlapSeconds >= 86400`，报告单独给出 `fullDayConcurrencyVerified`；短测的 95% 重叠容差不能用于宣称满 24 小时通过。

当前工具验证 Telnet 串口的持续输出、目录与归档下载链路，不覆盖 SSH 加密吞吐、设备真实日志压缩率、物理节点隔离、静默重连正确性及持续并发搜索/实时订阅压力。完整设计验收还需要这些场景，并须检查长测过程中的积压是否有界、每路文件可读 P99 是否达标。确定性合成正文的压缩率不能用于实际设备容量规划。
