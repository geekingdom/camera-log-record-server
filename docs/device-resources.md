# 设备资源与采集任务

## 主流程与身份

控制台以设备资源作为默认入口。先添加海康网络设备或串口服务器，再在资源下创建一个或多个日志任务。

资源名称仅用于展示。海康网络设备保存 IP、设备型号 `model`、短序列号 `subSerialNumber`、软件版本及最近创建认证时间；不使用长 `serialNumber` 替代短序列号。资源的 HTTP 登录凭据加密保存，查询接口不返回密码。采集任务的 SSH/Telnet 凭据单独配置，不假设它们与 ISAPI 账号相同。

资源提供添加、认证预览、分页查询、详情、版本编辑及软删除。任务仍使用原采集、命令、重连、实时打印、归档、查询和下载模块。

## 编辑与软删除

资源、任务、命令模板及后台配置保存修改前弹窗确认；任务启动、停止、暂停、继续，模板删除、账号撤销和日志作业取消同样先确认，取消不会提交修改请求。第三方 API 直接表达操作意图，编辑及删除资源必须携带版本号以防覆盖陈旧状态。

资源允许修改名称及 HTTP 凭据，密码留空保留已保存密码；网络资源编辑时会重新认证。IP 和资源类型不可修改，设备型号或短序列号发生变化时需新建资源，确保同一目录不会混入替换设备的日志。

资源删除前读取最新详情，在确认弹窗中显示关联任务总数、尚未停止数量和日志保留说明。确认后写入 `deletedAt`，将直接归属该资源以及引用该串口服务器的任务请求为停止，关闭过程继续复用采集任务生命周期。暂停任务的运行锁会被回收；数据库中途失败可由重复删除请求或调度周期重试。

删除资源不会删除任务记录、文件索引或已有日志文件。资源列表默认隐藏已删除项，勾选“包含已删除资源”可进入其历史日志。已删除资源禁止新建任务、编辑任务和重新启动采集；查询和下载仍可使用。日志仍遵循平台已配置的保留天数，软删除本身不会提前删除日志。

## 海康认证

输入资源名称、IP、用户名、密码和认证方式，摘要认证 `DIGEST` 为默认值，可切换 `BASIC`。点击“点击认证”后，服务端使用 GET 请求 `http://{IP}/ISAPI/System/deviceInfo`；IPv6 使用方括号。摘要认证由 HTTP 客户端完成挑战响应，只有最后的 401 被判定为用户名或密码错误，首次正常摘要挑战不视为失败。

只有 HTTP 200 且为合法完整 `DeviceInfo` XML 才认证成功。按命名空间解析型号、短序列号和 `firmwareVersion`、`firmwareReleasedDate`，后二者以空格拼接为软件版本。最终 401 返回凭据错误；非 200、网络异常、超时及无效设备信息均不能保存。认证操作只读取设备信息，不执行 debug，也不建立 SSH 采集连接。

前端修改认证输入后废弃先前预览，保存时服务端再次认证。客户端不能通过伪造型号、序列号或“已认证”标记绕过验证。串口服务器只需名称和 IP，不执行 ISAPI 请求。

## 任务约束

| 所属资源 | 任务协议 | 连接目标 |
| --- | --- | --- |
| 海康网络设备 | SSH | 锁定资源 IP，端口默认 22、可修改 |
| 海康网络设备 | Telnet 设备 | 锁定资源 IP，端口默认 23、可修改 |
| 海康网络设备 | Telnet 串口 | 选择已添加串口服务器并锁定其 IP，或手填串口服务器 IP；端口自行填写 |
| 串口服务器 | Telnet 串口 | 锁定当前串口服务器 IP，端口自行填写 |

新建任务必须带 `resourceId`。海康网络设备下串口任务选择已有服务器时再带 `serialServerResourceId`；自定义时该字段为 null 或省略。修改时传 null 可切换为自定义目标。服务端校验资源类型、认证记录和目标 IP。已保存任务不能通过 PATCH 更换所属资源。

不校验资源、IP 或端口重复。同一个设备可以创建并运行多个 22 端口 SSH 任务；数据库连接锁仅约束同一任务的运行归属。设备自身的连接数上限仍可能导致某次连接被设备拒绝。多个任务仍各自持有接收协程、命令队列和写入器，不按设备合并正文。

## 日志目录

海康网络资源的存储身份是规范 JSON 数组 `[IP, model, subSerialNumber]` 的 SHA-256，任务创建时由服务端生成并保存 `storageIdentity`。相同三元组即使资源名称或资源 ID 不同，也使用同一设备父目录；任一身份字段改变则使用另一目录。串口服务器以资源 ID 确定父目录。

```text
LOG_ROOT/
  resources/
    <storageIdentity>/
      <taskId>/
        <runId>/...
```

父目录下由服务自动创建任务和运行子目录，小时日志及片段在子目录中独立保存。资源名称、型号等不直接拼接文件系统路径，防止非法字符或路径穿越。每个采集任务必须持有 `storageIdentity`，写入器不会回退到任务 ID 或旧目录结构。

多节点部署时，以上是每个采集节点 `LOG_ROOT` 下的一致相对目录；节点本地磁盘不自动变成共享文件系统。跨节点片段仍由既有目录接口汇总及下载，不承诺自动搬迁为单台机器上的物理目录。

## 开发验证

本项目开发阶段统一使用资源结构，不维护历史独立任务兼容分支。需要重新建立开发环境时，先停止 API 和所有采集节点，确认任务与运行已结束，再显式执行 `python scripts/reset_development_data.py --confirm`。这是独立的开发重置命令，会清理开发任务、资源和日志，保留平台、节点、令牌和模板配置；控制台软删除接口不会调用它。

先验证资源 API、认证响应解析、任务资源约束及同端口调度，再执行前端构建和桌面/移动端浏览器回归。`scripts/verify_resource_workflow.py --browser` 使用本地模拟串口验证同端口双任务、真实浏览器实时和下载，以及资源软删除后归档继续下载，期间不会连接海康实体设备。

500 路持续 24 小时的容量与完整性验收仍需原计划的多节点压测，本次资源管理变更不代替该验收。
