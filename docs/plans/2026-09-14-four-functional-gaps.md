# 四项功能缺口实施计划

本计划承接当前状态总表。四项功能已完成本机实现和定向验证，最终证据见[四项功能改进验证记录](../history/2026-09-15-four-gaps-validation.md)；生产500路全天、新提交 CI、目标部署与物理多机验收仍另行保留，不能以本轮功能测试代替。

1. 节点输入速率准入：管理员配置`inputRateLimitMiB`，新增节点默认50 MiB/s、0禁用，历史配置不强制开启。候选筛选、事务领取与Worker建连前共同复核，超限不停止已有任务。真实Mongo已验证配置在领取快照期间收紧会回滚领取且无孤立run/lock，放宽后恢复；仍需目标多节点部署和真实持续吞吐验收。
2. 增长记录治理：`recordRetention`配置审计/事件/结束运行保留天数；维护任务有界领取，事务归档摘要和删除，不清活动/UNKNOWN/有效幂等及恢复引用。真实Mongo已验证摘要写入故障回滚、1001条命令分段、活租约互斥与过期恢复；`runs`、`commands`、`idempotency`、`operations`、`jobs`五类Explain均为10结果/10键/10文档且无SORT。仍需生产数据分布、长期索引和副本集成本验收。
3. 实时缺口补读：以时间/会话/目录游标查跨节点文件范围，前端依次读取已保存范围，保留无法补读的源缺口说明；已覆盖权限、分页、字节边界、迟到响应和1440/390/320页面。目录跨度超出24小时、500个文件或200个片段时明确转小时归档。仍需目标物理跨节点和真实持续采集验收。
4. 异常产物回收：持久输出归属、写入关闭证据、下载读者与清理互斥已实现；已覆盖写入/下载/维护竞争、取消、失联恢复、重复领取和受控路径。只回收具有明确关闭和归属证据的终态作业；未知归属的旧孤儿目录保守保留，不能称为全自动清除。仍需真实大文件断电、目标部署和多人持续下载验收。

主代理负责第1项及共享配置、后台维护、API目录、总表和集成；子代理分别负责2/3/4项及对应测试。所有手工编辑使用apply_patch，CodeGraph辅助影响定位，中文注释；不改真实设备与日志。完成定向验证后统一后端/前端/生产构建及浏览器回归，真实数据库测试仅用随机库并收尾删除。提交采用中文标题及背景/变更/测试/影响正文。
