# 手动命令准入与领取

`commands/manual_admission.py` 对当前任务运行和会话的 `MANUAL/QUEUED` 命令实行最多 100 条限制。已领取的 `SENDING` 不占待执行队列名额；其他任务、运行或旧会话独立计数。

## 原子边界

不能仅用独立的 count 和 insert：并发请求可能同时读到剩余一个名额并全部插入。正式入口现在使用 MongoDB 副本集 snapshot/majority 事务，先按任务、运行、节点、代次、会话、采集状态、运行意图和资源未删除条件递增 `commandClaimVersion`，再计数并插入命令。

同一任务的两个准入事务会争用同一任务文档；驱动重试回调时重新计数。停止、暂停、重连和归属变化与事务写冲突，条件失效返回 409。队列已满返回 429 并回滚任务声明版本。无需维护可能因异常收尾而泄漏的独立队列计数器。

命令 ID 由既有幂等入口在事务之外分配，事务重试不会换 ID。数据库异常继续交给既有幂等处理：已存在的固定 ID 可恢复返回，未确认结果使用原幂等键重试，禁止另建 ID 来追补命令。

## 领取与发送

`commands/manual_claim.py` 把归属复核、任务声明版本递增和当前会话 `QUEUED -> SENDING` 领取放入同一事务。旧会话排队记录的取消也须先在事务内确认当前实例仍有归属，避免过期实例修改后继记录。

领取成功后，运行时先复核当前会话，再把 `session_guard` 交给采集器唯一发送队列。采集器在 PSH 恢复探测之前和业务命令写入之前调用守卫，排队期间停止、接管或切换 collector 均不得继续写入。该守卫独立于定时命令预算回调，预算不会因两次检查而重复消耗。

明确失属且业务写入未开始时标记 `CANCELLED`；领取提交结果未知或数据库复核异常时不发送，保留 `UNKNOWN` 并记录异常。状态回写只更新原任务、运行、会话和命令的 `SENDING` 记录，不覆盖会话收尾已经写入的终态。

## 验证和限制

`tests/test_manual_admission.py`、`test_manual_command_ownership.py` 检查归属、会话、未知提交和实际采集器排队守卫；内存 Mongo 的无会话回调仅验证业务条件，不证明真实事务隔离。`scripts/verify_manual_admission.py` 在随机临时数据库中验证 110 请求恰好 100 条准入、准入/领取取消回滚、停止冲突和真实提交后确认丢失，结束后删除临时库，不建立设备连接。该脚本已接入 Linux 容器 CI。

数据库事务覆盖入队和领取，不覆盖设备 socket 写入，也没有将既有通用幂等审计改成与命令同一事务。最后一次归属检查与 socket 写入之间仍有跨系统窗口；跨节点接管必须继续要求旧实例确认停止或基础设施隔离，不能据此宣称整个命令生命周期已实现跨系统原子性。

该改动涉及采集 Worker。既有真实 Worker 未重启时不会自动使用新领取逻辑，须在受控暂停并确认连接释放后部署，不能同时运行两个实例争用同一会话。
