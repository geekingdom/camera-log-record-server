# 架构与设计

## 用户需求摘要

系统为设备日志提供持续采集、持久化、检索和交互能力。采集节点主动通过 SSH、Telnet 设备或 Telnet 串口连接设备，控制台和第三方通过正式 API 控制任务，浏览器通过 WebSocket 订阅日志。设备本身不使用 WebSocket。加时间前缀的正文保留在采集节点本地磁盘，MongoDB 保存配置、运行状态、命令预算、审计和文件目录，不逐行保存正文。

## 组件边界

```text
控制台 / 第三方 -> Nginx -> FastAPI API -> MongoDB 副本集
                             |                  |
                       内部鉴权接口          归属 / 状态 / 预算
                             |                  |
                             +---- 采集节点 ----+
                                    |     |
                         SSH / Telnet设备   顺序写入 -> 小时压缩进程
                            / Telnet串口            -> 查询与导出
```

## 源码目录

后端以职责分层，`backend/camera_logs/main.py` 保留 API 应用入口，`backend/camera_logs/worker.py` 保留 worker 启动兼容入口。公共配置、数据库、模型、安全与可观测性位于 `common/`；任务 API 和调度位于 `tasks/`；命令与模板位于 `commands/`；连接、collector 和会话运行时位于 `collection/`；日志 API、存储、归档、作业、保留及下载会话位于 `logs/`；节点 worker 与内部文件接口位于 `node/`；管理接口位于 `administration/`。

`scripts/` 放置本地验证、基准、设备注册和提交规则工具。`deploy/` 放置容器镜像、MongoDB 副本集初始化、Nginx 配置和 worker 启动脚本；`docs/` 记录接口、架构和运维边界。每个模块通过中文模块与函数说明描述职责，避免将设备凭据写入脚本或文档。

## 开发约定

修改前在项目根目录执行 `codegraph sync .` 同步索引；本服务当前重点使用 `codegraph impact SessionRuntime` 评估会话状态、实时帧和归档回调的影响范围。Python 源码以中文模块、类和公共函数说明标注职责，并按 `common/`、`tasks/`、`commands/`、`collection/`、`logs/`、`node/`、`administration/` 分目录维护，避免以单一巨型模块混合 API、连接和文件操作。提交前运行 `scripts/install-git-hooks.sh`，提交标题使用中文，正文按“背景、变更、测试、影响”四项记录；不要提交 `.env`、令牌、密码或本地压测产物。

`camera_logs.main:app` 是 HTTP 与 WebSocket 入口。`camera_logs.worker` 处理本地日志文件；每个 worker 以唯一 `NODE_ID` 注册，并公布其 `NODE_URL`。当 API 请求不在本机的文件时，根据路由记录转发到对应 `NODE_URL`，而不是共享本地路径。

初始化命令是有序数组。每条命令按自身换行符、延迟、提示符和超时设置单独发送，服务不会将多条命令拼接为 `;` 分隔的 shell 表达式，因此不会假设设备具备 shell 语义。Telnet 使用 IAC NOP 与 TCP keepalive；SSH 使用协议 keepalive。默认 `SSH_VERIFY_HOST_KEY=false`，连接显式禁用 AsyncSSH 的 `known_hosts` 主机密钥校验，不探测、不固定也不在 MongoDB 保存设备指纹；同 IP 和端口设备更换后直接按任务用户名和密码认证。默认连续 10 秒未收到日志时，collector 关闭会话并由运行时重连。

部署可通过 `SSH_VERIFY_HOST_KEY=true` 切换到可选严格模式。此时 worker 读取本机 `KNOWN_HOSTS` 文件并将其交给 AsyncSSH 约束连接；空路径、无效文件或主机密钥失配会在建立会话前失败，且不会自动重试。`known_hosts` 只属于部署配置，不是任务配置、API 数据或 MongoDB 跨节点状态；默认模式和严格模式都不会把主机密钥登记交给普通控制台用户。

## 日志行时间前缀

collector 在收到设备输出块时，以该块首字节到达服务器的时间生成 Asia/Shanghai 前缀，格式固定为 `[YYYY-MM-DD HH:MM:SS] `。每个以 LF 或 CRLF 结束的逻辑行只添加一次前缀；一行跨多个网络分包时不会重复添加，空行也保留前缀和原始换行符。该转换在写入 `HourlyWriter` 前完成，因此小时原始文件、归档、下载、搜索结果和实时 WebSocket 尾随内容一致，均为已加前缀的日志字节。前缀改变了原始字节数和 SHA-256 摘要，不能将改造前的摘要直接用于当前归档比对。

每个小时分段采用 `任务名-设备IP-上海自然小时起始-结束-run短ID-session短ID-part序号` 的可读文件 stem，raw、index 和 `.tar.gz` 归档共享此 stem。任务名按 UTF-8 字节限制截断并过滤路径与控制字符，IPv6 地址将冒号改为连字符；分段号既扫描新格式，也兼容旧的 `part-*.log` 和 `part-*.tar.gz`，确保重连和升级不会覆写历史文件。文件逻辑 ID 仍由相对路径计算，命名变化不改变 ID 算法。

MongoDB 使用 `rs0` 三成员副本集，应用 URI 必须携带 `replicaSet=rs0`。副本集提供元数据可用性，不复制 worker 的本地日志目录；需要跨主机保留原始文件时，应使用经评审的备份或对象存储方案。

## 安全边界

每条连接的接收与发送各由一个协程处理；每个会话独占写入器和行首前缀状态。接收先处理原始提示符，再添加时间前缀；内容相同的设备日志完整保留。按照 256 KiB 或 100 ms 批量提交，每秒对正文和索引执行 `fsync`，封存时强制同步。崩溃前最后一个同步周期仍属于风险窗口。

压缩在每节点一个独立 spawn 进程执行，使用 gzip 级别 1；正文及索引摘要和大小均经解压校验，临时文件同步后原子发布，最后删除未压缩文件。连接释放在归档之前完成，停止操作仍等待最终落盘。网络读取失败允许重连；写入结果不确定时禁止整批重试，并上报阻塞或错误。

SSH 暂停保留运行 ID、定时预算和端点锁，关闭连接并禁用重试；继续重新初始化并生成新会话。停止后再启动产生新运行，预算归零。初始化、手动和定时命令共用唯一发送队列，发送前持久化定时预算；结果不确定不退回次数、不自动补发。

部署目标为 8 个节点、500 路总并发、每节点上限 100 路。按每行设备正文 256 字节计算，600,000 行/秒产生 153.6 MB/s 正文；22 字节服务器前缀额外增加 13.2 MB/s，写入约 166.8 MB/s，日正文加前缀约 14.41 TB，尚不含索引、临时副本和服务日志。必须以真实输出验证压缩率、积压、磁盘同步延迟和容量；短时合成测试不证明 24 小时集群验收或 P99 指标。

`ENCRYPTION_KEY` 必须为 Fernet 密钥，`BOOTSTRAP_TOKEN` 只用于首次管理员初始化，均只能从密钥管理系统或受限环境注入。反向代理在生产环境终止 TLS，API 和 MongoDB 不直接暴露至公网。`NODE_URL` 必须是 API 可达的受控内部地址，不能由不可信设备任意指定。默认 SSH 认证只依赖任务账号密码；若部署启用严格主机密钥校验，`KNOWN_HOSTS` 也必须作为节点本地受控密钥材料管理。

API 与 worker 使用队列式 JSONL 日志。访问日志记录 request ID、主体、方法、路由、状态和耗时，不记录请求 body 或 query；模块和操作失败使用异常追踪记录。密码、令牌、Authorization 和加密密码字段会递归脱敏。
