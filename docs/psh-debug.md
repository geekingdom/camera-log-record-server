# PSH 调试切换

部分设备首次连接后处于 Protect Shell（PSH）。采集器发送 `debug` 命令时，会先完成 PSH 到 ASH 的受控切换，再发送该条目之后的命令。本说明定义该握手的适用范围、配置方法、观测方式和敏感信息边界。

## 适用范围与命令顺序

以下场景中的 `debug` 都使用同一套 PSH/ASH 握手：

- 初始化命令条目中的 `debug`。
- 定时命令条目中的 `debug`。
- 通过 API 或控制台下发的 manual `debug`。

采集器可以从横幅识别模式；缺少可靠横幅时，先执行 `ls`。明确返回 `'ls' Not Supported, Try 'help'` 并回到提示符时判定 PSH；本次 `ls` 正常回显或返回目录且回到提示符、没有错误时判定 ASH。仅收到普通提示符或无关打印不能判定成功。已经确认是 ASH 时不会发送口令，而是跳过切换并继续执行。PSH 状态下，`ls` 探测、`debug`、备用口令唤起命令、口令写入和 ASH 确认都在会话唯一发送队列中完成，因此其他初始化、手动或定时命令不会插入这段交互。

定时命令预算按定时命令条目的命令 ID 原子预留。一个 `debug` 定时项从握手开始到确认结束只消耗一次预算；内部协议步骤不分别记为多次执行。

初始化命令应保留为独立且有序的条目，示意顺序如下：

1. `debug`
2. `outputClose`
3. `outputOpen`
4. `setDebug -m all -l 7 -d 111`
5. `prtHardInfo`

不要将这些命令用分号拼接为单个 shell 字符串。只识别去除首尾空白后完全等于 `debug` 的独立条目，`echo debug` 等普通命令不触发握手。其余条目在 ASH 可用后按配置顺序发送，具体业务命令仍须符合目标设备支持的语法。

## 挑战值与口令获取

PSH 设备在二维码流程后输出挑战值。采集器接受以下两种来源格式：独立的一整行 Base64 字符串，以及 `enc_string:<完整Base64源字符串>`。它取 `Password:` 提示符之前最后一条完整的有效来源，并将**完整、原始的 Base64 源字符串**作为 HTTP JSON 的 `source` 字段发送：

```json
{
  "source": "<完整Base64源字符串>",
  "userName": "<配置的用户名>"
}
```

这里的 Base64 只用于格式校验，不会先解码再作为 `source` 传输。文档、服务运行日志、审计事件和排障记录不展示密文、口令或解密服务端响应原文。原始设备日志仍完整保存设备输出的二维码、密文及提示符，遵循任务日志的访问权限；发送口令不会主动写入原始日志，设备自身回显仍属于原始打印。

串口响应按增量流解析，不要求一次 read 返回完整内容。格式明确的设备 syslog 记录只从握手观察窗口移除，支持它们插入 Base64、Password 提示或 ASH 横幅内部；跨网络分包保留未完成片段。已识别的完整密文独立保留，持续普通打印不会把它从等待状态中挤掉。未知输出不被猜测为可删除日志，原始日志写入完全不受旁路过滤影响。

确认需要切换后发送 `debug`。仅当旧版设备明确报告不支持该命令或命令列表时，才允许一次 `zhimakaimen` 备用尝试；普通登录横幅中的 help 不触发备用命令。取得口令后，口令只写入设备连接，不加入命令记录、服务日志、审计事件或数据库状态。观察到 ASH 横幅即确认成功；没有横幅但已回到命令提示符时，再用 `ls` 验证。若不能确认 ASH，当前 `debug` 命令失败；采集是否继续由下述命令通道恢复结果决定。

Telnet 串口握手默认以 100 ms 字符间隔发送，避免突发输入在受限串口命令行中丢失或错收；设置 `PSH_SERIAL_CHARACTER_INTERVAL` 可调整为 0～1 秒。节奏只影响模式探测与解密握手，不限制日志接收速率，也不改变其他业务命令。握手仍使用对应命令配置的换行符；实机 `10003` 的 `ls` 探测使用 CR（`\r`）验证通过。

## 配置模式

`PSH_MODE=disabled` 是默认配置。未明确启用时，PSH 设备不能请求口令，避免因部署遗漏而把调试请求发送到未知服务。

### 本地 Mock

本地开发或合成验证可设置 `PSH_MODE=mock`，并通过 `PSH_MOCK_PASSWORD_FILE` 指向本地 JSON 文件。该文件每次取用时重新读取，键必须严格采用 `protocol:ip:port`：

```json
{
  "SSH:192.168.1.34:22": "<SSH-34-占位口令>",
  "SSH:192.168.1.35:22": "<SSH-35-占位口令>",
  "TELNET_SERIAL:192.168.1.8:10003": "<映射到-34-的占位口令>"
}
```

本地三端点映射为：SSH `.34` 使用 `.34` 的条目，SSH `.35` 使用 `.35` 的条目，`TELNET_SERIAL` `.8:10003` 使用映射到 `.34` 的条目。端口 `10002` 的设备尚未确认，**不配置**对应映射。示例中的所有口令都是占位符；Mock 文件属于敏感本地配置，不能提交仓库、打印到控制台或上传到工单。

### 生产 HTTP

生产环境显式设置 `PSH_MODE=http`，并由受限环境或密钥管理系统注入以下配置：

```dotenv
PSH_MODE=http
PSH_TOKEN_URL=<OAuth-token-endpoint>
PSH_API_URL=<password-decrypt-endpoint>
PSH_CLIENT_ID=<client-id>
PSH_CLIENT_SECRET=<client-secret>
PSH_API_KEY=<api-key>
PSH_USER_NAME=<user-name>
```

HTTP 模式保留 OAuth client credentials 流程获取访问令牌，再调用解密接口。解密接口成功时仅从响应的 `data.data` 读取口令。若服务返回业务码 `403003`，提供器只刷新一次令牌并重放一次解密请求；不会无限重试。单个网络请求超时为 4 秒，整个口令获取流程超时为 9 秒。

不得在 `.env.example`、文档、源码、工单、截图或普通服务日志中记录真实 client ID、client secret、API key、用户名、访问令牌、挑战值、口令、密文或解密响应。

## 会话行为与观测

接收协程是唯一的设备数据读取者。PSH 对话只观察接收到的数据，不消费、不修改也不绕过正常日志写入。对话缓冲区有上限，防止异常设备输出无限占用内存。

默认规则仍是连续 10 秒未收到设备实际日志输出即关闭连接；协议控制流量和握手本身不改变这条规则。关闭后由运行时既有的重连策略建立新会话。

PSH 到 ASH 任一步骤失败只会结束当前 `debug` 命令，不会把采集任务置为 ERROR、停止日志接收、关闭连接或触发自动重连。失败后，采集器在同一发送队列中仅写入 Ctrl-C（`\x03`，不携带口令），先等待新的 shell 提示符且确认其中不含 `Password:`，再以 `ls` 探测恢复状态。若未确认提示符，超时或恢复写入失败，则绝不发送 `ls`；若恢复成功，后续初始化、手动和定时的普通命令可以继续按原顺序发送；日志接收始终不受该探测影响。

若 Ctrl-C、提示符确认或 `ls` 探测未能确认恢复，采集仍持续，原始日志照常写入。每个后续初始化、手动或定时命令都可在唯一发送队列中重新尝试 Ctrl-C、等待新的无 Password 提示符并完成 `ls` 探测；成功后才发送当前命令，不再要求用户另发 debug 才能解除状态。恢复仍未确认时，当前初始化项跳过、手动命令记录 `FAILED`；未发送的定时项不占用预算、不创建执行记录，等待完整间隔后继续探测，不结束该项调度。日志接收不被中断。

已进入发送阶段的定时 `debug` 保留其占用的一次预算，并将本次执行记为 `FAILED`。后续 `debug` 是独立握手，不自动重发前次挑战码。网络重连后的新会话也允许再次执行初始化 `debug`。设备持续停在密码输入状态是明确的执行边界：在确认 shell 前不会把业务命令误作口令提交。

设备连续输错调试口令可能锁定 SSH debug（用户反馈一般为连续五次），锁定后再次输入 debug 可能不再返回二维码和密文。平台不会把单次握手的内部步骤做成自动重试：每个 `debug` 命令最多提交一次口令。后续初始化或定时 `debug` 是独立命令，可在安全恢复后重新尝试；空响应、普通提示符、孤立 Password 提示或持续业务打印均不足以调用解密提供器，也不会导致该次命令的口令重发。无响应本身不是锁定的确证，解锁方式和恢复时间由设备侧确认，不假定重连或等待即可解锁；命令通道未确认恢复时，手动命令会明确报告失败。

成功、已处于 ASH 和失败等状态会写入 `events` collection，事件类型为 `DEBUG_MODE`，其中包含阶段和 shell 模式，以及任务、运行和会话标识。对应任务可查询：

- `tasks.shellMode`：例如 `UNKNOWN`、`PSH` 或 `ASH`。
- `tasks.debugPhase`：当前或最后一次调试切换阶段。

每个新会话开始时，运行时将任务状态重置为 `shellMode: "UNKNOWN"` 与空的 `debugPhase`。`DEBUG_MODE` 事件和任务状态均不得包含 challenge、口令、token 或远端响应正文。

## 验收边界

两路真实 SSH 设备已使用离线 Mock 口令完成 `ASH_READY` 并继续初始化。真实串口 `10003` 已验证 `ls` 判定为 PSH，也能提取完整 348 字符密文；该串口提交给定口令后明确返回 `Incorrect Password. 0 Times Left`，因此停止口令重试，不能声称该端口已进入 ASH。需要核对串口该次密文对应的有效口令后另行验收。

真实本地 Telnet 协议模拟服务器覆盖 syslog 插入密文、Password 提示和 ASH 横幅内部的交互，确认唯一连接、命令顺序与原始日志保留。HTTP 合同仅用 MockTransport 测试，本机未请求实际解密接口。设备时间、口令有效期及生产解密接口连通性仍需部署环境验证。
